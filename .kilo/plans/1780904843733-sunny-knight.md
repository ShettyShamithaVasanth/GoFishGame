# Fix 4 Matchmaking Errors — Plan Update

## The 4 Errors

### Error 1: `MatchmakingUIController.cs:72` — Type `Lobby` not found
Missing `using Unity.Services.Lobbies.Models;`. The `Lobby` type on line 72 is unresolved.

**Fix**: Add `using Unity.Services.Lobbies.Models;` at the top of `MatchmakingUIController.cs`.

---

### Error 2: `MatchmakingUIController.cs:94` — `Player` type ambiguity
The project has a global `Player` class (`core/Player.cs`) AND `Unity.Services.Lobbies.Models.Player`. Even after adding the using directive, `Player player = lobby.Players[i]` becomes ambiguous.

**Fix**: Use fully qualified type `Unity.Services.Lobbies.Models.Player` at line 94. Or use a using alias:
```csharp
using LobbyPlayer = Unity.Services.Lobbies.Models.Player;
```
Then: `LobbyPlayer player = lobby.Players[i];`

---

### Error 3: `QuickMatchService.cs:275-278` — `FindMatch()` throws `NotImplementedException`
`MatchMakingStarter.cs:16` calls `QuickMatchService.Instance?.FindMatch()` but `FindMatch()` just throws. The actual implementation is `FindMatchAsync()`.

**Fix**: Replace the `FindMatch()` stub in `QuickMatchService.cs` with a fire-and-forget async wrapper:
```csharp
public void FindMatch()
{
    _ = FindMatchAsync();
}
```
This way `MatchMakingStarter.cs` doesn't need to change — it calls `FindMatch()` which internally calls the async method.

---

### Error 4: `MatchmakingUIController.cs:106` — `LobbyManager.Instance` is null in GameScene
`MenuController.PlayOnline()` loads "GameScene" via `SceneManager.LoadScene()`, which unloads the menu scene where `LobbyManager` lives. So `LobbyManager.Instance` is null in GameScene. Accessing `LobbyManager.Instance.avatarDatabase.avatarSprites[avatarIndex]` → NullReferenceException.

**Fix**: `QuickMatchService` already has `[SerializeField] private AvatarDatabase avatarDatabase;` (line 68). Expose it via a public property, then use `QuickMatchService.Instance.avatarDatabase` instead of `LobbyManager.Instance.avatarDatabase` in `MatchmakingUIController`.

Additionally, add null/bounds safety:
- Check `player.Data != null` and `player.Data.ContainsKey("name")` before accessing
- Check `avatarIndex` bounds against `avatarSprites.Length`
- Fallback to "Player" name and null avatar when data is missing

   ```csharp
   private void UpdatePlayerSlots(string playerId, int avatar, int count)
   {
       var lobby = QuickMatchService.Instance?.CurrentLobby;
       if (lobby == null) return;

       var db = QuickMatchService.Instance?.AvatarDB;
       string localPlayerId = AuthenticationService.Instance.PlayerId;

       for (int i = 0; i < playerSlots.Length; i++)
       {
           if (i >= lobby.Players.Count)
           {
               playerSlots[i]?.SetProfile("Waiting...", null);
               continue;
           }

           var player = lobby.Players[i];
           string name = "Player";
           int avatarIndex = 0;
           Sprite avatarSprite = null;

           // Get name/avatar from lobby data
           if (player.Data != null)
           {
               if (player.Data.ContainsKey("name"))
                   name = player.Data["name"].Value;
               if (player.Data.ContainsKey("avatar"))
                   int.TryParse(player.Data["avatar"].Value, out avatarIndex);
           }

           // Get avatar sprite safely
           if (db != null && db.avatarSprites != null
               && avatarIndex >= 0 && avatarIndex < db.avatarSprites.Length)
           {
               avatarSprite = db.avatarSprites[avatarIndex];
           }

           playerSlots[i]?.SetProfile(name, avatarSprite);
       }
   }
   ```
