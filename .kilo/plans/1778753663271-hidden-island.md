# Fix 2 Online Bugs — Deck + Animation Order

## Bug 1: Deck Not Visible on Host

**Root cause**: `CreateDeckVisual()` (GameManager.cs line 328-331) uses `DOVirtual.DelayedCall(0.5f, ...)` to activate card objects. This DOTween delayed call may not fire during online initialization on host. Compare with `UpdateDeckVisualCount()` (line 382) which uses immediate `SetActive(true)` and works.

### Fix — GameManager.cs `CreateDeckVisual()` lines 328-331

Change the activation to immediate in online mode:
```csharp
if (GameModeManager.isOnlineMode)
{
    cardObj.SetActive(true);  // immediate for online
}
else
{
    DOVirtual.DelayedCall(0.5f, () =>
    {
        if (cardObj != null) cardObj.SetActive(true);
    }).SetLink(cardObj);  // delayed for offline (original behavior)
}
```

Offline mode behavior is UNCHANGED.

## Bug 2: Cards Appear in Hand Before Animation Finishes

**Root cause**: In `NetworkGameManager.cs`, `BroadcastStateToAll()` runs IMMEDIATELY after `TurnResultClientRpc()` in all 3 places:

- Line 346 (Go Fish Phase 1)
- Line 352 (Success path)
- Line 444 (Go Fish Phase 2)

Timeline:
1. `TurnResultClientRpc` → starts `PlayTurnResultCoroutine` (runs over ~4 seconds with animations)
2. `BroadcastStateToAll` → runs IMMEDIATELY → sends `SyncPrivateHandClientRpc` → `ApplyPrivateHand()` → `RefreshAllHands()` → **cards appear in hand instantly**
3. Animation plays AFTER cards already visible — wrong order!

The `PlayTurnResultCoroutine` already handles local state updates and `RefreshAllHands()` at the RIGHT time (after animations). So `BroadcastStateToAll` is just a safety sync that should be delayed.

### Fix — NetworkGameManager.cs (3 lines)

Replace all 3 `BroadcastStateToAll()` calls with delayed sync:

**Line 346** (Go Fish Phase 1):
```csharp
// OLD: BroadcastStateToAll();
// NEW:
StartCoroutine(DelayedStateSync(5f));
```

**Line 352** (Success path):
```csharp
// OLD: BroadcastStateToAll();
// NEW:
StartCoroutine(DelayedStateSync(5f));
```

**Line 444** (Go Fish Phase 2):
```csharp
// OLD: BroadcastStateToAll();
// NEW:
StartCoroutine(DelayedStateSync(5f));
```

5 seconds gives all animations time to complete (SUCCESS: ~4s, GO FISH: ~3-4s). `PlayTurnResultCoroutine` handles the correct local state updates after animations, so the delayed sync is just a safety correction.
