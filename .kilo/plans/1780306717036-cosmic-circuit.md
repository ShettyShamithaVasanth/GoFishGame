# Fix: Online Animation Order — Book → Deck Empty → Card Animation to Hand

## Problem

In online "Play with Friends" mode, when a player's hand becomes empty after forming a book:

**Current (broken):**
1. Book animation plays
2. **Simultaneously**, refill cards appear in the hand (visually placed)
3. **Then** deck-to-hand animation plays (redundant — cards already visible)

**Expected (matches offline):**
1. Book formation animation (completes fully, hand becomes empty)
2. Deck gradually empties (one card removed per refill)
3. Card animation from deck to player's hand (cards appear ONLY through animation)

## Root Cause

### The state sync corrupts the hand MODEL mid-animation

`NetworkGameManager.DelayedStateSync` fires at **2.5–5 seconds** and calls `BroadcastStateToAll()`. This sends `SyncPrivateHandClientRpc` which calls `ApplyPrivateHand`:

```
ApplyPrivateHand (line 1795):
  players[myId].PlayerHand.Clear();              ← Model updated to FINAL state
  foreach (int value in hand)
      players[myId].AddCard(ConvertToCard(value)); ← Includes refill cards!
  if (!turnActionRunning)
      RefreshAllHands();                          ← Only visual is gated, MODEL IS WRONG
```

**The model is updated to the final state (book removed + refill cards added) while animations are still playing (~7+ seconds).** Only the visual refresh is gated, but the model corruption means every subsequent `RefreshAllHands()` call inside `PlayTurnResultCoroutine` shows the wrong state.

Same issue in `ApplyPublicState` (line 1756) — other players' dummy card counts are also updated to final state.

### The online animation code does NOT update the model (unlike offline)

**Offline** updates the model incrementally during each animation step:
```csharp
// TransferCardsWithAnimation (line 1170):
AnimateCardMove(...) → players[toID].AddCard(c)         ← Model updated

// HandleBook (line 1492):
AnimateCardMove(...) → player.PlayerHand.RemoveCard(c)   ← Model updated

// RefillHandIfEmpty (line 971):
RemoveTopDeckVisual()
AnimateCardMove(...) → player.AddCard(drawn)              ← Model updated
```

**Online** does NOT update the model during animation — it relies entirely on state sync.

## Solution — 6 Changes in GameManager.cs

### Change 1: Guard `ApplyPrivateHand` entirely during animation (line 1795)

Block the ENTIRE method (including model update) when `turnActionRunning` is true:

```csharp
public void ApplyPrivateHand(int[] hand)
{
    if (turnActionRunning) return;  // ← NEW: Block model + visual during animation
    
    if (players == null || playerIdToClientId.Count == 0)
        return;
    int myId = GetLocalPlayerId(NetworkManager.Singleton.LocalClientId);
    if (myId == -1) { Debug.LogError("My PlayerID not found ❌"); return; }
    
    players[myId].PlayerHand.Clear();
    foreach (int value in hand)
        players[myId].AddCard(ConvertToCard(value));
    RefreshAllHands();  // ← Always refresh (whole method is gated now)
}
```

### Change 2: Guard `ApplyPublicState` entirely during animation (line 1756)

Same pattern — block everything during animation:

```csharp
public void ApplyPublicState(ulong[] ids, int[] scores, int[] cardCounts)
{
    if (turnActionRunning) return;  // ← NEW: Block model + visual during animation
    
    if (players == null || activePlayers == null)
        return;
    
    int myId = GetLocalPlayerId(NetworkManager.Singleton.LocalClientId);
    
    for (int i = 0; i < ids.Length; i++)
    {
        int localId = GetLocalPlayerId(ids[i]);
        if (localId == -1) continue;
        players[localId].SetScore(scores[i]);
        if (localId != myId)
        {
            int currentCount = players[localId].PlayerHand.Cards.Count;
            int targetCount = cardCounts[i];
            if (currentCount != targetCount)
            {
                players[localId].PlayerHand.Clear();
                for (int j = 0; j < targetCount; j++)
                    players[localId].AddCard(new Card(0, CardSuit.Spade));
            }
        }
    }
    RefreshAllHands();  // ← Always refresh (whole method is gated now)
}
```

### Change 3: SUCCESS case — update model during transfer animation (lines 2244-2261)

After each transfer `AnimateCardMove`, add card to asker's model. Then remove transferred cards from target's model:

```csharp
// After the existing transfer animation loop (line 2245-2257):

// Add transferred cards to asker's model
foreach (int cardValue in data.transferredCards)
{
    Card card = ConvertToCard(cardValue);
    yield return StartCoroutine(
        AnimateCardMove(targetUI.transform, askerUI.transform, card, asker.PlayerID)
    );
    players[asker.PlayerID].AddCard(card);  // ← NEW
}

// Remove transferred cards from target's model
int myLocalId = GetLocalPlayerId(NetworkManager.Singleton.LocalClientId);
if (target.PlayerID == myLocalId)
{
    foreach (int cardValue in data.transferredCards)
    {
        Card c = ConvertToCard(cardValue);
        var hand = players[target.PlayerID].PlayerHand.Cards;
        int idx = hand.FindIndex(h => h.Rank == c.Rank && h.Suit == c.Suit);
        if (idx >= 0) hand.RemoveAt(idx);
    }
}
else
{
    for (int i = 0; i < data.transferCount; i++)
    {
        if (players[target.PlayerID].PlayerHand.Cards.Count > 0)
            players[target.PlayerID].PlayerHand.Cards.RemoveAt(0);
    }
}

RefreshAllHands();
targetUI.HideTargetPopup();
```
