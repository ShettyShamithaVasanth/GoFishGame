# Plan: Fix Online Hand Refill & Game Over in Go Fish

## Problem

In **online mode** (Play with Friends), two critical features are missing that work correctly in offline mode:

1. **Hand Refill**: When a player's hand becomes empty (after forming a book or losing all cards), cards are NOT drawn from the deck. This causes the game to get stuck — the player can't select a rank or take any action.

2. **Game Over Detection**: There is no game over logic in online mode. When the deck runs out, the game continues indefinitely instead of showing the game over panel with scores.

## Root Cause Analysis

### Offline (works correctly):
- `HandleBook()` → calls `RefillHandIfEmpty()` → draws up to 5 cards from deck → animates → refreshes UI
- `EndTurn()` / `DrawCardWithAnimation()` → checks `deck.CardCount() == 0` → calls `TriggerGameOver()`
- `TriggerGameOver()` → shows `GameOverUI.ShowGameOver()` with sorted scores

### Online (broken):
- `NetworkGameManager.CheckForBook()` removes book cards but **never refills** empty hands
- `NetworkGameManager.RefillHandIfEmpty()` in `GameManager.cs` has `if (GameModeManager.isOnlineMode) { yield break; }` — it bails out
- `RequestCardRpc()` and `RequestDrawFromDeckRpc()` have **no deck-empty → game over** logic
- No `GameOverClientRpc` exists to notify clients the game ended
- `GameOverUI` only has `ShowGameOver(Player[])` — no method for network player data

## Files to Modify

| File | What Changes |
|------|-------------|
| `NetworkGameManager.cs` | Add server-side refill, game over detection, new RPCs, extend TurnResultData |
| `GameManager.cs` | Handle refill data in `PlayTurnResultCoroutine`, handle network game over |
| `GameOverUI.cs` | Add `ShowNetworkGameOver()` for online mode |

## Detailed Changes

### 1. Extend `TurnResultData` struct (NetworkGameManager.cs)

Add these fields to communicate refill and game over to clients:

```csharp
public bool refillNeeded;
public ulong refillPlayerClientId;
public int[] refillCards;
```

Update `NetworkSerialize()` to serialize the new fields.

### 2. Server-Side Hand Refill (NetworkGameManager.cs)

**New private method: `ServerRefillIfEmpty()`**
```
- Input: NetworkPlayer
- If player.hand.Count > 0 → return empty array (no refill needed)
- drawCount = Min(5, deck.Count)
- Draw drawCount cards from NetworkDeckManager
- Add each card to player.hand
- Update deckRemainingCards NetworkVariable
- Return drawn cards as int[]
```

**Modify `RequestCardRpc()` (success path)**:
- After `CheckForBook(sender)` completes:
  - Call `ServerRefillIfEmpty(sender)` → store refill data in result
  - Also check if **target** has empty hand after losing cards → refill target too
    - Use a separate mechanism: store target refill in result fields like `targetRefillNeeded`, `targetRefillCards`, `targetRefillPlayerClientId`
    - OR send a separate RefillClientRpc right after
- After refill, check `NetworkDeckManager.Instance.deck.Count == 0` → trigger game over

**Modify `RequestCardRpc()` (go fish path)**:
- The pending draw is set. After the draw happens in `RequestDrawFromDeckRpc`, refill will be checked there.

**Modify `RequestDrawFromDeckRpc()`**:
- After `CheckForBook(sender)`:
  - Call `ServerRefillIfEmpty(sender)` → store refill data in result
- After draw, check `NetworkDeckManager.Instance.deck.Count == 0`:
  - If deck empty AND no refills possible → trigger game over
- When `drawnCard == -1` (deck already empty):
  - Trigger game over instead of just calling `NextTurn()`

**Modify `NextTurn()`**:
- Before setting the next player, check if their hand is empty
- If empty and deck has cards → refill their hand first
- If empty and deck is empty → skip their turn (or trigger game over if all players empty)

### 3. Server-Side Game Over (NetworkGameManager.cs)

**New method: `ServerCheckGameOver()`**
```
- If deck.Count > 0 → return false (not over yet)
- Check if ANY player still has cards AND valid moves exist
- If no player can make a move → game over
- Return true
```

**New method: `ServerTriggerGameOver()`**
```
- Collect from NetworkPlayerManager: clientId, playerName, score, avatarIndex for each player
- Determine winner (highest score, tie-break by book order)
- Send GameOverClientRpc with all data
```

**New ClientRpc: `GameOverClientRpc()`**
```
Parameters: ulong[] clientIds, string[] names, int[] scores, int[] avatarIndices
- On each client, find GameManager and call TriggerNetworkGameOver()
```

### 4. Client-Side Handling (GameManager.cs)

**Modify `PlayTurnResultCoroutine()`**:

After the book handling in both CASE 1 (success) and CASE 3 (go fish phase 2):

```
if (data.refillNeeded) {
    // 1. Find the refill player's UI
    // 2. For each refill card, animate from deckPosition to player UI
    // 3. The state sync will update the actual hand data
    // 4. RefreshAllHands()
    // 5. Show toast: "[PlayerName] drew new cards from deck"
}
```

**New method: `TriggerNetworkGameOver(ulong[] clientIds, string[] names, int[] scores, int[] avatarIndices)`**:
```
- Set gameOver = true
- Cancel all invokes and coroutines
- Disable all player interaction
- Find the local player (check IsHuman)
- Create a Player[] array from the network data for GameOverUI compatibility
- Call gameOverUI.ShowGameOver() or a new ShowNetworkGameOver()
```

### 5. GameOverUI.cs

**New method: `ShowNetworkGameOver()`**
```
Parameters: string[] names, int[] scores, int[] avatarIndices, bool[] isLocalPlayer
- Same logic as ShowGameOver but using network player data directly
- Sort by score descending
- Show avatar, name, score for each player
- Highlight the local player's row
```

### 6. TurnResultData Extended Fields

Full list of new fields:
```csharp
public bool refillNeeded;
public ulong refillPlayerClientId;
public int[] refillCards;
```

For simplicity, handle one refill per turn result. If both asker and target need refills, the asker's refill is in the result, and the target's refill is handled by the next state sync + a separate RefillHandClientRpc.

Actually, for the cleanest approach, handle the **primary** refill (book-forming player) in `TurnResultData`, and handle the target refill via the state sync that already happens after each turn. The state sync already sends correct hand data, so the client's view will update. The only thing missing is the animation, which we can add via a dedicated refill notification.

**Alternative (simpler) approach for target refill**: After `RequestCardRpc` success, check if target hand is 0 → call a separate `RefillHandClientRpc` just for the target. This keeps `TurnResultData` clean.

## Implementation Order

1. **TurnResultData** — Add `refillNeeded`, `refillPlayerClientId`, `refillCards` fields + serialization
2. **NetworkGameManager** — Add `ServerRefillIfEmpty()` method
3. **NetworkGameManager** — Modify `RequestCardRpc()` to call refill after book
4. **NetworkGameManager** — Modify `RequestDrawFromDeckRpc()` to call refill after book  
5. **NetworkGameManager** — Add `ServerCheckGameOver()` + `ServerTriggerGameOver()` + `GameOverClientRpc`
6. **NetworkGameManager** — Add game over checks in `RequestCardRpc`, `RequestDrawFromDeckRpc`, and `NextTurn()`
7. **GameManager** — Handle `refillNeeded` in `PlayTurnResultCoroutine()` with animations
8. **GameManager** — Add `TriggerNetworkGameOver()` method
9. **GameOverUI** — Add `ShowNetworkGameOver()` method
10. **Test** — Verify both offline and online modes work without regressions

## Offline Mode Safety

- All new code in `NetworkGameManager` is server-only (gated by `IsServer` checks)
- `GameManager` changes in `PlayTurnResultCoroutine` are gated by `if (!GameModeManager.isOnlineMode) return` at the top
- `RefillHandIfEmpty()` offline logic remains untouched
- `GameOverUI.ShowGameOver()` offline method remains untouched
- New methods in `GameOverUI` are additive only

## Edge Cases to Handle

1. **Deck has exactly 1-4 cards left when refill needed** → draw whatever is available
2. **Multiple players need refill simultaneously** → handle asker first, target via state sync
3. **Deck empties during refill** → game over after refill completes
4. **Player draws last card from deck (Go Fish)** → check game over after draw
5. **All books completed (13 books)** → deck naturally empty → game over
6. **Player has 0 cards at start of turn in online** → `NextTurn()` should refill before setting turn
