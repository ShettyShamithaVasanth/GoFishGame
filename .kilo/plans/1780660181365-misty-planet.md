# Plan — Matchmaking Panel: Show All Players (Host + Clients) in Real Time

## 1. Problem Statement

When a user clicks **Play Online** → the **Matchmaking Panel** opens, but:

- Only the **local** player's name/avatar is shown (slot 0).
- When **other** players click Play Online, their name/avatar does **NOT** appear in the host's panel (or anyone else's).
- When the host is in the panel and a client joins, the client's panel does **NOT** show the host.
- The matchmaking timer just counts down 20 s and falls back to offline — no actual Unity Lobby is ever created.

Expected (professional Go Fish multiplayer, like the Friends-Lobby panel):
- Each connected player fills a `PlayerProfileUI` slot (name + avatar) in **every** client's matchmaking panel.
- When enough players are found (>=2), the game **auto-starts**.
- Offline mode and Play-with-Friends mode must remain 100% untouched.

## 2. Root Cause Analysis

| File | Current Behavior | Problem |
|------|------------------|---------|
| `MatchMakingStarter.cs:10-58` | Sets local `myProfileUI` only, calls `QuickMatchService.FindMatch()`, never contacts Lobby SDK | No lobby created → other players cannot join → slots never update |
| `QuickMatchService.cs:37-43` | `FindMatch()` only flips `isSearching=true` and starts timer | Stub. Never queries/creates lobbies. Never invokes `OnPlayerJoined/OnPlayerLeft/OnMatchFound` |
| `MatchmakingUIController.cs:54-57` | `StartSearching()` only toggles panel on. `Update()` only reads timer. | Never updates `playerSlots[]` from lobby data |
| `LobbyManager.cs` | Has working `CreateLobby/JoinLobby/UpdatePlayerSlotsUI` but those are **only** used by the Friends flow | Matchmaking does not use it |
| `OfflineFallback.cs:9` | Calls `QuickMatchService.Cancel()` | OK — but `Cancel()` does nothing network-wise today |

The `MatchmakingUIController` already has `public PlayerProfileUI[] playerSlots` (4 slots wired up in the scene at GameScene.unity:17190-17194) and a `QuickMatchService.avatarDatabase` reference. The plumbing exists — the **logic** is missing.

## 3. Solution Overview (Event-Driven MVC)

```
┌────────────────────────────────────────────────────────────────────────┐
│                         PLAY ONLINE FLOW                               │
└────────────────────────────────────────────────────────────────────────┘

  User A clicks "Play Online"
       │
       ▼
  MenuController.PlayOnline()  →  GameModeManager.isOnlineMode = true
       │                         → SceneManager.LoadScene("GameScene")
       ▼
  MatchMakingStarter.Start()
       │   (returns early if !isOnlineMode  →  offline UNAFFECTED)
       ▼
  QuickMatchService.FindMatch()        ◄── Controller (matchmaking)
       │
       ├─► MatchmakingUIController.StartSearching()   ◄── View (shows panel + timer)
       │
       ├─► QueryLobbiesAsync(filter: isMatchmaking=true, availableSlots>0)
       │       │
       │       ├─ found ─► JoinMatchmakingLobby(code)
       │       └─ none  ─► CreateMatchmakingLobby()
       │
       ├─► UpdatePlayerAsync(name + avatar)   (write my data to lobby)
       ├─► CreateRelay() / JoinRelay()         (start Netcode host/client)
       ├─► RefreshAndPublish()                 (raise OnPlayerJoined events)
       │
       ▼
  [POLLING every pollInterval seconds]
       │
       ├─► GetLobbyAsync
       ├─► Diff player list vs previous snapshot
       ├─► Raise OnPlayerJoined / OnPlayerLeft with (slotIndex, name, avatarIdx)
       │
       ▼
  MatchmakingUIController (subscribes to events)
       │
       ├─► OnPlayerJoined(slotIndex, name, avatarIndex)
       │       → playerSlots[slotIndex].SetProfile(name, avatarSprite)
       ├─► OnPlayerLeft(slotIndex)
       │       → playerSlots[slotIndex].SetProfile("Waiting...", null)
       └─► OnMatchFound()  → statusText = "Match Found!"
       │
       ▼
  [When players.Count >= requiredPlayers]
       │
       ├─► QuickMatchService.HandleMatchFound()
       │     → raises OnMatchFound
       │     → after delay, calls LobbyManager.StartGameForMatchmaking()
       │           → same path as Friends StartGame
       │           → NetworkGameManager.InitializeAndDeal()
       │
  [Timeout (searchTimeout) OR Cancel]
       │
       └─► CleanupAndLeave()  →  RemovePlayerAsync + (DeleteLobbyAsync if host)
                                 + NetworkManager.Shutdown()
       │
       ▼
  OfflineFallback.Enter()  (only on timeout)  →  ModeSelectionPanel "Offline"
```

**New fields**:
```csharp
[Header("Config")]  // all already serialized — keep
[SerializeField] private int requiredPlayers = 4;
[SerializeField] private float searchTimeout = 20f;
[SerializeField] private float pollInterval  = 2.5f;   // NEW (was commented out)
[SerializeField] private int    maxLobbySize = 4;      // NEW
[SerializeField] private float  matchFoundDelay = 1.5f; // NEW (UX buffer before StartGame)

[Header("Dependencies")]
[SerializeField] private AvatarDatabase avatarDatabase;  // already there

[Header("Runtime")]
private Lobby currentLobby;
private Lobby previousLobbySnapshot;   // for diffing on poll
private bool  isHost;
private string localPlayerId;
private float searchTimer;
private float pollTimer;
private bool  isSearching;
private bool  matchFoundHandled;       // guard so OnMatchFound fires once
```

**New methods** (all `async`, all wrapped in `try/catch` calling `OnError`):

1. `public async void FindMatch()`
   - Set `isSearching = true`, reset timers.
   - Cache `localPlayerId = AuthenticationService.Instance.PlayerId`.
   - `MatchmakingUIController.Instance.StartSearching()`.
   - `await FindOrCreateLobbyAsync()`.
   - On success → call `PublishSnapshot()` (raise `OnSlotUpdated` for every player in lobby).
   - On exception → `OnError?.Invoke(msg)` → fallback to offline via `OfflineFallback.Enter()`.

2. `private async Task FindOrCreateLobbyAsync()`
   - `QueryLobbiesAsync` with filters:
     - `AvailableSlots > 0`
     - `Data["isMatchmaking"] == "true"` (using `S1` index key or `Data1` field)
     - Order by `CreatedAt` desc (oldest first → fill existing lobbies before creating new ones)
     - `Count = 1`
   - If a result exists → `JoinMatchmakingLobby(result.LobbyCode)`.
   - Else → `CreateMatchmakingLobby()`.

3. `private async Task CreateMatchmakingLobby()`
   - `isHost = true`.
   - `CreateLobbyAsync("MM_" + Guid(N).Substring(0,6), maxLobbySize)`.
   - `UpdatePlayerAsync` → write `name` + `avatar` (VisibilityOptions.Member).
   - `CreateRelayAllocationAsync(maxLobbySize)` → returns `relayJoinCode`.
   - `UpdateLobbyAsync` → write `relayCode` (Member), `isMatchmaking` (Public) data keys.
   - `currentLobby = await GetLobbyAsync(...)`.
   - Cache snapshot. Raise events for self only.
   - `NetworkManager.Singleton.StartHost()` (via the configured transport).

4. `private async Task JoinMatchmakingLobby(string lobbyCode)`
   - `isHost = false`.
   - `JoinLobbyByCodeAsync(lobbyCode)`.
   - `UpdatePlayerAsync` → write `name` + `avatar`.
   - `currentLobby = await GetLobbyAsync(...)`.
   - Cache snapshot. Raise events for ALL existing players (host + earlier joiners).
   - `JoinRelayAllocationAsync(currentLobby.Data["relayCode"].Value)`.
   - `NetworkManager.Singleton.StartClient()`.

5. `private void Update()` (modified)
   - If `!isSearching` → return.
   - `searchTimer += dt` → if `>= searchTimeout` → `HandleTimeout()`.
   - `pollTimer += dt` → if `>= pollInterval` → `_ = PollLobbyAsync()`.
   - `MatchmakingUIController.Instance.UpdateTimerDisplay(RemainingSeconds)` (move text out of view).

6. `private async Task PollLobbyAsync()`
   - `currentLobby = await GetLobbyAsync(currentLobby.Id)`.
   - Diff against `previousLobbySnapshot`:
     - For each new player → raise `OnSlotUpdated(slotIndex, name, avatarIdx)`.
     - For each removed player → raise `OnSlotCleared(slotIndex)`.
   - Update snapshot.
   - If `currentLobby.Players.Count >= requiredPlayers` and `!matchFoundHandled`:
     - `matchFoundHandled = true`.
     - `OnMatchFound?.Invoke()`.
     - If host → `StartCoroutine(StartMatchAfterDelay(matchFoundDelay))`.

7. `private IEnumerator StartMatchAfterDelay(float delay)`
   - `yield return new WaitForSeconds(delay)`.
   - Call `LobbyManager.StartGameForMatchmaking()` (new public helper — see File 2).
     This re-uses the existing start-game flow (hides panels, calls `NetworkGameManager.InitializeAndDeal`).

8. `public async void Cancel()` (modified)
   - `isSearching = false`.
   - `await CleanupAsync()`.
   - Hide matchmaking panel.

9. `private async Task CleanupAsync()`
   - If `currentLobby != null`:
     - `RemovePlayerAsync(currentLobby.Id, localPlayerId)`.
     - If was host → `DeleteLobbyAsync(currentLobby.Id)`.
   - `currentLobby = null; previousLobbySnapshot = null; matchFoundHandled = false;`.
   - If `NetworkManager.Singleton.IsListening` → `Shutdown()`.

10. `private void HandleTimeout()`
    - `isSearching = false`.
    - `OnTimeout?.Invoke()` (existing — used by `MatchmakingUIController.HandleTimeout` → `OfflineFallback.Enter`).
    - `_ = CleanupAsync()`.

**Relay helpers** (private, in this file to keep `LobbyManager` untouched as much as possible — these mirror `LobbyManager.CreateRelay/JoinRelay` but on `currentLobby` of this service):

```csharp
private async Task<string> CreateRelayAllocationAsync(int maxPlayers) { ... }
private async Task JoinRelayAllocationAsync(string relayJoinCode)     { ... }
```

> **Why duplicate ~30 lines instead of reusing `LobbyManager.CreateRelay`?**
> The `LobbyManager.CreateRelay` writes the `relayCode` to **its own** `currentLobby` field. Sharing it would entangle the two controllers' state. Duplicating keeps `QuickMatchService` self-contained — proper MVC. A future refactor could extract a `RelayTransportHelper` static class; that is **out of scope** for this change to avoid touching `LobbyManager`'s working Friends flow.

### File 3 — `Assets/Scripts/MatchmakingUIController.cs`  (REWRITE — pure View)

**Goal**: Subscribe to `QuickMatchService` events. No direct Lobby/Relay/Network references.

```csharp
using UnityEngine;
using TMPro;

public class MatchmakingUIController : MonoBehaviour
{
    public static MatchmakingUIController Instance;

    [Header("UI Binding")]
    public GameObject panel;
    public PlayerProfileUI[] playerSlots;     // 4 slots, assigned in scene
    public TextMeshProUGUI statusText;
    public TextMeshProUGUI timerText;

    [Header("Config")]
    [SerializeField] private string searchingText = "Searching for players...";
    [SerializeField] private string matchFoundText = "Match found! Starting game...";
    [SerializeField] private string waitingSlotText = "Waiting...";

    private AvatarDatabase avatarDB;

    void Awake()
    {
        Instance = this;
        avatarDB = QuickMatchService.Instance != null
            ? QuickMatchService.Instance.GetAvatarDatabase()  // new helper
            : null;
    }

    void OnEnable()
    {
        var svc = QuickMatchService.Instance;
        if (svc == null) return;
        svc.OnSlotUpdated += HandleSlotUpdated;
        svc.OnSlotCleared += HandleSlotCleared;
        svc.OnMatchFound  += HandleMatchFound;
        svc.OnTimeout     += HandleTimeout;
        svc.OnError       += HandleError;
    }

    void OnDisable()
    {
        var svc = QuickMatchService.Instance;
        if (svc == null) return;
        svc.OnSlotUpdated -= HandleSlotUpdated;
        svc.OnSlotCleared -= HandleSlotCleared;
        svc.OnMatchFound  -= HandleMatchFound;
        svc.OnTimeout     -= HandleTimeout;
        svc.OnError       -= HandleError;
    }

    public void StartSearching()
    {
        panel.SetActive(true);
        ResetAllSlots();
        if (statusText != null) statusText.text = searchingText;
    }

    public void UpdateTimerDisplay(float remainingSeconds)
    {
        if (timerText != null)
            timerText.text = "TIMER : " + Mathf.Ceil(remainingSeconds) + "s";
    }

    // ---------- event handlers (View ← Controller) ----------

    void HandleSlotUpdated(int slotIndex, string playerName, int avatarIndex)
    {
        if (slotIndex < 0 || slotIndex >= playerSlots.Length) return;
        var slot = playerSlots[slotIndex];
        if (slot == null) return;
        Sprite spr = ResolveAvatar(avatarIndex);
        slot.SetProfile(playerName, spr);
    }

    void HandleSlotCleared(int slotIndex)
    {
        if (slotIndex < 0 || slotIndex >= playerSlots.Length) return;
        playerSlots[slotIndex]?.SetProfile(waitingSlotText, null);
    }

    void HandleMatchFound()
    {
        if (statusText != null) statusText.text = matchFoundText;
    }

    void HandleTimeout()
    {
        StartCoroutine(TimeoutFallbackRoutine());
    }

    void HandleError(string message)
    {
        Debug.LogWarning("[MatchmakingUI] Error: " + message);
        // Errors fall through to timeout-like fallback handled by OfflineFallback
    }

    // ---------- UI helpers ----------

    void ResetAllSlots()
    {
        if (playerSlots == null) return;
        foreach (var s in playerSlots)
            s?.SetProfile(waitingSlotText, null);
    }

    Sprite ResolveAvatar(int idx)
    {
        if (avatarDB == null || avatarDB.avatarSprites == null) return null;
        if (idx < 0 || idx >= avatarDB.avatarSprites.Length) return null;
        return avatarDB.avatarSprites[idx];
    }

    // ---------- cancel button (wired in scene) ----------

    public void OnCancelClicked()
    {
        Debug.Log("Matchmaking cancelled by user");
        QuickMatchService.Instance?.Cancel();
        panel.SetActive(false);
        GameModeManager.isOnlineMode = false;
        var menu = FindAnyObjectByType<MenuController>();
        if (menu != null && menu.MenuUI != null) menu.MenuUI.SetActive(true);
    }

    IEnumerator TimeoutFallbackRoutine()
    {
        if (statusText != null) statusText.text = "No players found. Switching to offline...";
        yield return new WaitForSeconds(1.5f);
        panel.SetActive(false);
        GameModeManager.isOnlineMode = false;
        OfflineFallback.Enter();
    }
}
```

**Notes**:
- `Update()` is removed from this file (timer text update moves into the controller; view provides `UpdateTimerDisplay(remaining)` called by controller). This is cleaner MVC — view does not pull from model.
- The `statusText` field is **already declared** on the existing class (line 11) — already wired in the scene.
- The `playerSlots[]` array is **already declared and wired** in the scene (4 slots at GameScene.unity:17190-17194).
- All text values are `[SerializeField] private string` — **no hardcode**, designer-tweakable.

## 8. Why This Works for All 3 Modes

### Offline
- `MenuController.PlayOffline` → `isOnlineMode = false`. `MatchMakingStarter.Start()` returns at line 1.
- `QuickMatchService` is dormant. `MatchmakingUIController` is dormant (panel hidden).
- `GameManager.SetupGame` runs the AI / offline flow as today.

### Play with Friends (Host)
- `MenuController.PlayWithFriends` → `FriendsPanel` → "Create Room" → `LobbyManager.CreateLobby()`.
- `LobbyManager.currentLobby` is set, `lobbyPanel` shown, `UpdatePlayerSlotsUI()` runs.
- **None of these methods is modified.**
- `QuickMatchService.currentLobby` stays null — no event overlap.

### Play with Friends (Client)
- Same as host but `JoinLobby(code)` → `JoinRelay()`. Untouched.

### Play Online (NEW — Host side)
- `MenuController.PlayOnline` → `isOnlineMode = true` → loads `GameScene`.
- `MatchMakingStarter.Start` → `QuickMatchService.FindMatch()`.
- `QueryLobbiesAsync` finds no matchmaking lobby → `CreateMatchmakingLobby()`:
  - Lobby created, host's `name`+`avatar` written.
  - Relay allocation created, `NetworkManager.StartHost()`.
  - Snapshot cached → `OnSlotUpdated(0, myName, myAvatar)` → host's slot 0 shows host.
- Polling every 2.5 s. Host's `panel` shows timer + slot 0.

### Play Online (NEW — Client side, joins host)
- Same entry. `QueryLobbiesAsync` finds the host's lobby → `JoinMatchmakingLobby(code)`:
  - Joins lobby, client's `name`+`avatar` written.
  - `JoinRelay` → `NetworkManager.StartClient()`.
  - Snapshot iterates ALL lobby players → raises `OnSlotUpdated(0, hostName, hostAvatar)` AND `OnSlotUpdated(1, myName, myAvatar)`.
  - **Client's panel shows both host and self immediately.**

### Both sides stay in sync
- Host's polling detects new client → diff → raises `OnSlotUpdated(1, clientName, clientAvatar)` → host's slot 1 fills.
- Client's polling is a no-op until host leaves or match starts.

### Match Found
- Both sides hit `players.Count >= requiredPlayers`.
- Both raise `OnMatchFound` → `statusText = "Match found!"`.
- Host only: starts `StartGameForMatchmaking()` after `matchFoundDelay` (1.5 s UX buffer).
- `NetworkGameManager.InitializeAndDeal()` runs on host → `isGameStarted.Value = true` replicates → all clients' `OnGameStartedChanged` hides the matchmaking panel and shows the game scene UI.

### Timeout (no other players)
- `searchTimer >= searchTimeout` → `HandleTimeout()` → `OnTimeout` event.
- `MatchmakingUIController.HandleTimeout` → shows "No players found" → `OfflineFallback.Enter()` (unchanged).
- `CleanupAsync()` removes the player, deletes the lobby if host, shuts down Netcode.

### Cancel (user clicks Cancel)
- `OnCancelClicked` → `QuickMatchService.Cancel()` → `CleanupAsync()` → panels hide, menu returns.
- Mirrors existing `LobbyManager.CloseLobby` behavior, scoped to the matchmaking lobby only.

| T12 | 3-player online | Build A → Play Online; Build B → Play Online; Build C → Play Online; set `requiredPlayers = 3` | All three see each other in slots 0/1/2. Auto-start at 3. |

## 11. Edge Cases Handled

| Edge Case | Handling |
|-----------|----------|
| Two clients race to create lobbies | `QueryLobbiesAsync` returns whichever was created first (ordered by `CreatedAt` asc). Second client joins it instead of creating. |
| Lobby deleted between query and join | `JoinLobbyByCodeAsync` throws `LobbyServiceException(LobbyNotFound)` → caught → fall back to `CreateMatchmakingLobby()`. |
| Relay allocation fails | Caught → `OnError?.Invoke("Relay failed")` → `MatchmakingUIController` shows error → `OfflineFallback`. |
| Host never writes `relayCode` before client joins | Client's `JoinMatchmakingLobby` retries `GetLobbyAsync` until `Data["relayCode"]` present (max 5 retries × 0.5 s). |
| Same player joins twice (reconnect) | Unity Lobby SDK returns existing player. Snapshot diff sees no change → no duplicate event. |
| `requiredPlayers` > lobby max | Config error; log warning at `FindMatch` start, clamp `requiredPlayers = Mathf.Min(requiredPlayers, maxLobbySize)`. |
| Player leaves after match found but before StartGame | Host's `StartGame` checks `currentLobby.Players.Count >= 2`; if not, aborts and resets `matchFoundHandled = false` so a new match can be found. |
| `AuthenticationService` not signed in | `FindMatch` early-returns with `OnError("Not signed in")` → `OfflineFallback`. |
