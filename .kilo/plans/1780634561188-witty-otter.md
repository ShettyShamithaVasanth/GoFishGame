# Plan — QuickMatch Timeout → Offline Mode-Selection Fallback

## Goal
When the QuickMatch (online) 20-second search timer reaches 0, the game must cleanly transition to the **offline mode-selection panel** (same UX as the existing Play Offline path), let the user pick 2/3/4 players, and start an offline AI game — without breaking:
- Direct offline play (`MenuController.PlayOffline`)
- Play-with-Friends lobby (create/join/start)
- Online gameplay when a match IS found within 20 s
- Online-mode state tracking (`GameModeManager.isOnlineMode`)

## Root cause (why "nothing happens" at 0 s today)
1. **Duplicate timers racing.** `QuickMatchService` (Inspector `searchTimeout = 20 s`) and `MatchmakingUIController.timer = 20f` both count 20 s independently. Whichever fires first leaves the other in an inconsistent state.
2. **Fallback path is fragile.** `MatchmakingUIController.HandleNoPlayersFound()` first tries `LobbyManager.Instance.modeSelectionPanel`. In the GameScene (loaded by `MenuController.PlayOnline`) that panel reference is often null/destroyed, the code falls through to `MenuController`, but in that scene `MenuUI`, `LoadingPanel`, etc. are already in odd states. Net result: the matchmaking panel hides, the mode-selection panel either isn't in the scene or is hidden behind something, and the user is stranded — "stops there itself".
3. **`ModeSelectionController.PlayGame()` is incomplete.** Even if the panel does open, clicking Play only does `GameManager.SetActive(true)` + `gameSceneUI.ShowPanel()` — it never enables the per-seat player GameObjects (Top/Bottom/Left/Right) and never calls `GameManager.SetupGame()`. So nothing visible happens after the user picks a count.
4. **Misleading header.** Fallback panel header is set to "Online Mode" which is wrong (it's a fallback to offline).
5. **State leakage.** `GameModeManager.isOnlineMode` is only flipped to false in some branches; if the LobbyManager branch fires, the offline `GameManager.SetupGame()` will still hit online-only code paths.

## Design principles (MVC + no hardcode)
- **Model**: `GameModeManager.isOnlineMode`, `ModeSelectionController.selectedPlayers` — already exist, no change.
- **View**: `MatchmakingUIController`, `ModeSelectionController`, `MenuController` — only react to events from controllers, never own timeouts.
- **Controller**: `QuickMatchService` owns the **single canonical timeout** and emits events. `MenuController.ContinueGame()` becomes the **single canonical "start an offline game now"** entry point used by both the normal offline flow and the timeout fallback.
- **No hardcode**: timeout value stays a `[SerializeField]` on `QuickMatchService`. Player count is read from `ModeSelectionController.selectedPlayers` (already data-driven). No magic GameObject.Find strings; all references flow through existing serialized fields.
- **Idempotent**: re-entering the fallback path or pressing Play twice must be safe.

## Changes (by file)

### 1. `Assets/Scripts/QuickMatchService.cs` — make it the single timer source
- Keep `searchTimeout` as the only timeout.
- Expose a **read-only `RemainingSeconds`** property: `Mathf.Max(0, searchTimeout - searchTimer)`.
- Expose a **read-only `IsSearching`** property.
- `FindMatch()` — actually start `isSearching = true` and reset `searchTimer = 0` (today it's a no-op stub; the parallel UI timer is the only reason anything counts down).
- `HandleTimeout()` — keep firing `OnTimeout`; also expose `OnTimerTick` (optional, only if we want the UI to subscribe to ticks; UI can also just poll `RemainingSeconds` in its own `Update`). **Decision: poll** — fewer allocations, no per-frame delegate, simpler MVC.
- `LeaveLobbyAndCleanup()` — also reset `isSearching = false` (already does via `HandleTimeout`).
- Add a `Cancel()` public method (currently `OnCancelClicked` lives on the UI; service should own cancellation so callers don't poke private state). UI's cancel button calls `Cancel()` then closes the panel.

### 2. `Assets/Scripts/MatchmakingUIController.cs` — view only, no own timer
- **Delete** the local `float timer = 20f` and `IEnumerator SearchTimer()`. The UI's `timerText` now reads `QuickMatchService.Instance.RemainingSeconds` once per frame in `Update` (guarded by `QuickMatchService.Instance != null && QuickMatchService.Instance.IsSearching`).
- `StartSearching()` — just `panel.SetActive(true)`. Service owns state.
- `StopSearching()` / `OnCancelClicked()` — call `QuickMatchService.Instance.Cancel()` then hide panel; restore menu (same as today, but cleaner: delegate to `MenuController` if present, otherwise leave to caller).
- **Replace `HandleNoPlayersFound()`** with a lean, deterministic fallback:
  1. `searching = false`
  2. `timerText.text = "No players found. Switching to offline..."`
  3. `yield return new WaitForSeconds(1.5f);`  (per user choice: short message then jump)
  4. Hide matchmaking panel.
  5. `GameModeManager.isOnlineMode = false;`  — **single source of truth**, set exactly once.
  6. Call a **new static helper** `OfflineFallback.Enter()` (see file 5 below) which opens `MenuController.ModeSelectionPanel` (the one already wired up in the scene) with header `"Offline"`.
- Remove all the `LobbyManager.Instance.modeSelectionPanel` vs `MenuController.ModeSelectionPanel` branching — that's what made the current code fragile. There's exactly one path.

### 3. `Assets/Scripts/ModeSelectionController.cs` — route through MenuController
- `PlayGame()` — replace body with a delegation call:
  ```csharp
  public void PlayGame()
  {
      gameObject.SetActive(false);
      var menu = FindAnyObjectByType<MenuController>();
      if (menu != null) menu.ContinueGame();
      else Debug.LogError("MenuController missing — cannot start game");
  }
  ```
- This makes the offline-flow's `Play Offline` button and the fallback's `Play` button go through the **same** code path (`MenuController.ContinueGame`), eliminating the "user picks count, nothing happens" bug for both flows.
- No change to `Select2/3/4`, `SetHeader`, coin slider, etc.

### 4. `Assets/Scripts/MenuController.cs` — make `ContinueGame()` idempotent
- `ContinueGame()` already enables Top/Bottom/Left/Right based on `ModeSelectionController.selectedPlayers` and calls `GameManager.SetupGame()`. The only adjustment:
  - Guard against double-init: if `GameManager.GetComponent<GameManager>().IsInitialized()`-style check (offline variant — we may need a light `isOfflineSetupDone` bool) is already true, early-return.
  - Hide `MenuUI` and `LoadingPanel` defensively at entry (already does for ModeSelectionPanel; add the other two so the fallback path doesn't leave them visible from a previous state).
- No change to `PlayOffline`, `PlayOnline`, `PlayWithFriends`, `JoinRoom`, `CloseFriendsPanel`. The friends lobby flow is untouched.

### 5. NEW small static helper: `Assets/Scripts/OfflineFallback.cs`
Centralizes "go to offline mode-selection right now" so the view doesn't reach into MenuController's serialized fields:
```csharp
public static class OfflineFallback
{
    public static void Enter()
    {
        // 1) Make sure online mode is off (caller already did this; safety net).
        GameModeManager.isOnlineMode = false;

        // 2) Stop any pending matchmaking/lobby cleanup on the service side.
        QuickMatchService.Instance?.Cancel();

        // 3) Find the scene's MenuController and route through its loading flow
        //    so the UX matches Play Offline exactly (loading → mode select).
        var menu = UnityEngine.Object.FindAnyObjectByType<MenuController>();
        if (menu == null)
        {
            UnityEngine.Debug.LogError("OfflineFallback: MenuController not found in scene.");
            return;
        }

        // Hide anything the matchmaking flow may have left visible.
        if (menu.MenuUI != null) menu.MenuUI.SetActive(false);
        if (menu.LoadingPanel != null) menu.LoadingPanel.SetActive(false);

        // Open the mode-selection panel directly with the Offline header.
        if (menu.ModeSelectionPanel != null)
        {
            menu.ModeSelectionPanel.SetActive(true);
            var ctl = menu.ModeSelectionPanel.GetComponent<ModeSelectionController>();
            if (ctl != null) ctl.SetHeader("Offline");
        }
    }
}
```
This is the only place that knows the string "Offline". The view layer (`MatchmakingUIController`) just calls `OfflineFallback.Enter()` and is done.

### 6. Scene / prefab wiring (manual, in Unity Editor — flagged in plan, not edited by code)
- Verify the GameScene (loaded by `MenuController.PlayOnline`) has a `MenuController` with `ModeSelectionPanel`, `GameManager`, `TopPlayer`, `BottomPlayer`, `LeftPlayer`, `RightPlayer`, `DeckPosition`, `gameSceneUI` all assigned. If any are null in that scene, the fallback can't work — no amount of code fixes that.
- Verify `QuickMatchService` GameObject persists into GameScene (DontDestroyOnLoad, or placed in GameScene). Its `[SerializeField] searchTimeout = 20f` is the single timeout value used by both view and service.

## Files NOT touched (preserved)

- `NetworkGameManager.cs` — multiplayer gameplay unchanged.
- `GameManager.cs` — offline `SetupGame()` and online `InitializeMultiplayer()` unchanged.
- `GameOverUI.cs`, `PauseManager.cs`, `ConfirmQuitManager.cs`, `AskUI.cs`, `UIPlayer.cs` — unchanged.

## MVC trace (sanity check after implementation)
| Concern | Owner |
|---|---|
| "Is this an online session?" | Model: `GameModeManager.isOnlineMode` |
| "How many players?" | Model: `ModeSelectionController.selectedPlayers` |
| "Is the search running? How much time left?" | Controller: `QuickMatchService` |
| "Show seconds on screen, hide panel on timeout" | View: `MatchmakingUIController` (subscribes to service, no own timer) |
| "Open mode selection on timeout" | Controller helper: `OfflineFallback.Enter()` |

## Validation (manual test matrix)
1. **Offline happy path** — Main menu → Play Offline → Loading → Mode Select → pick 4 → Play → game starts with 4 AI seats. ✓ unchanged.
2. **Offline mode 2 / 3** — Same as #1 with 2 and 3 — correct seats enabled. ✓ unchanged.
3. **Play with Friends — Host** — Create Lobby → friend joins → Start → online game starts. ✓ unchanged.
4. **Play with Friends — Join** — Enter code → Join → host presses Start → game starts. ✓ unchanged.
5. **QuickMatch — match found within 20 s** — `OnMatchFound` fires → online game starts via `StartOnlineGame()`. ✓ unchanged.
6. **QuickMatch — timeout (the bug)** — Timer hits 0 → "No players found. Switching to offline..." for ~1.5 s → matchmaking panel hides → mode-select panel opens with header "Offline" → pick 2/3/4 → Play → offline game starts with the chosen number of AI players. ✅ **NEW: works end-to-end.**
7. **QuickMatch — user cancels mid-search** — Cancel button → matchmaking panel hides, returns to main menu, `isOnlineMode = false`. ✓ unchanged behavior.
8. **QuickMatch — fallback then Play then Play Again** — After fallback game ends, Play Again should restart the offline game (calls `GameManager.RestartGame()` → `SetupGame()`). ✓ unchanged.
9. **Double-click Play on mode select** — `ContinueGame()` is idempotent; second click is a no-op. ✅ **NEW: safe.**
10. **Logs** — `[QUICKMATCH] timeout at 20.00s`, `[OFFLINE-FALLBACK] entering`, `[OFFLINE-FALLBACK] mode-selection panel active`, `[MENU] ContinueGame players=4`. Easy to trace in Console.

## Risk / rollback
- The change is additive + a few targeted edits. No scene asset changes are required by code; only Inspector checks (already a precondition for the existing offline flow).
- If anything regresses, revert these 5 files and delete `OfflineFallback.cs`. The offline and online-with-friends paths were not edited and remain functional.
