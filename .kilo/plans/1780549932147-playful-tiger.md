# Fix Plan: Client-Side Matchmaking Fallback — UnassignedReferenceException

## Problem

When a client clicks "Play Online" → matchmaking panel appears for 20 seconds → no players found → the client crashes with:

```
UnassignedReferenceException: The variable MenuUI of MenuController has not been assigned.
```

at `MatchmakingUIController.cs:59` (`menu.MenuUI.SetActive(false)`).

On the host side this works because the `MenuController` in that scene/context has all inspector references properly assigned. On the client side, `MenuUI` is null.

## Root Cause Analysis

`MatchmakingUIController.HandleNoPlayersFound()` (line 47-69) accesses `menu.MenuUI`, `menu.LoadingPanel`, and `menu.ModeSelectionPanel` without any null checks. When these references are unassigned in the inspector (client-side GameScene), Unity throws `UnassignedReferenceException`.

The same unsafe pattern exists in `OnCancelClicked()` (line 78-92) which also accesses `menu.MenuUI` directly.

Additionally, the method only tries `MenuController` references and ignores `LobbyManager` which has equivalent panel references (`modeSelectionPanel`, `matchmakingPanel`, `menuBackground`) that ARE properly assigned in the GameScene.

## Fix: 2 files changed

### 1. `MatchmakingUIController.cs` — Add null-safe panel transitions

**`HandleNoPlayersFound()`** — Use `LobbyManager` as primary reference source (it's always available in GameScene for online flows), with `MenuController` as fallback. Add null guards on every panel access.

**`OnCancelClicked()`** — Add null guard on `menu.MenuUI` access.

**Both methods** — Reset `GameModeManager.isOnlineMode = false` since the fallback is offline play.

### 2. No changes to offline gameplay, Play with Friends, or lobby flow

The fix only touches the matchmaking timeout/cancel paths, which are exclusive to the "Play Online" flow.

## Detailed Changes

### File: `Assets/Scripts/MatchmakingUIController.cs`

#### `HandleNoPlayersFound()` — Replace the current method body:

- Hide matchmaking panel (already done)
- Try `LobbyManager.Instance` first for panel references:
  - `lm.menuBackground?.SetActive(false)` 
  - `lm.modeSelectionPanel?.SetActive(true)` with header set via its `ModeSelectionController`
- Fallback to `MenuController` if LobbyManager panels are unavailable:
  - Null-check `menu.MenuUI`, `menu.LoadingPanel`, `menu.ModeSelectionPanel` before each `.SetActive()`
- Set `GameModeManager.isOnlineMode = false` (offline fallback)

#### `OnCancelClicked()` — Add null guard:

- Wrap `menu.MenuUI.SetActive(true)` in `if (menu.MenuUI != null)` check
- Also reset `GameModeManager.isOnlineMode = false`

### Files NOT Modified

| File | Reason |
|------|--------|
| `GameManager.cs` | Offline gameplay unchanged |
| `NetworkGameManager.cs` | Online game start unchanged |
| `LobbyManager.cs` | Lobby / friends flow unchanged |
| `MenuController.cs` | Offline menu unchanged |
| `ModeSelectionController.cs` | Mode selection logic unchanged |

## Verification

After the fix:
1. Client clicks "Play Online" → matchmaking starts → 20s timeout → **mode selection panel appears** (no crash)
2. Host clicks "Play Online" → matchmaking starts → 20s timeout → mode selection panel appears (unchanged behavior)
3. Cancel matchmaking → returns to menu background (no crash)
4. Offline "Play Offline" → works as before
5. "Play with Friends" → lobby/gameplay unaffected
