# Fix: Online Mode — Drawn/Transferred/Refill Cards Not Visible in Hand + Book Refill Animation Order

## Problems

### Problem 1: Drawn card hidden after Go Fish draw (user-reported)
In online mode, when Player A asks Player B for rank 2, Player B doesn't have it → Go Fish → Player A draws from deck → **the drawn card is NOT visible in Player A's hand**. It only becomes visible when the next action happens.

### Problem 2: Book refill cards appear before animation (previous issue)
When a book formation empties the player's hand and triggers a refill, the refill card **immediately appears** in the hand BEFORE the deck-to-hand animation plays.

Correct behavior (already working in offline mode):
1. Card drawn/transferred → animation plays from source to hand
2. Card **appears in hand** after animation lands
3. Book formation → hand shown **empty**
4. Refill card(s) animate from deck → appear after landing

## Root Cause

Both problems share the same root cause: **the online mode animation code never adds cards to the player's hand data**.

### Offline mode (correct pattern):
```
AnimateCardMove() → players[toID].AddCard(c) → RefreshAllHands()
```
- `TransferCardsWithAnimation` line 1170: `players[toID].AddCard(c)` after each animation
- `DrawCardWithAnimation` line 1271: `players[currentPlayer].AddCard(drawn)` after animation
- `RefillHandIfEmpty` line 971: `player.AddCard(drawn)` after each animation

### Online mode (broken pattern):
```
AnimateCardMove() → RefreshAllHands()  ← card never added to data!
```
- CASE 1 SUCCESS line 2244-2257: transferred cards animated but **never added**
- CASE 3 GO FISH line 2499-2508: drawn card animated but **never added**
- Refill loops (2338-2354, 2594-2609): refill cards animated but **never added**

The cards only appear through `DelayedStateSync → ApplyPrivateHand` which runs at unpredictable times (2.5s or 5s after the server processes the turn). When it fires during animation, `ApplyPrivateHand` updates the hand DATA but skips visual refresh (`if (!turnActionRunning) RefreshAllHands()`). After animation ends (`turnActionRunning = false`), no explicit `RefreshAllHands()` is called — the card remains hidden until the next action.

**Timeline for the drawn card issue:**
```
t=0.0s  Client receives TurnResultClientRpc → starts PlayTurnResultCoroutine
t=0.0s  Draw animation starts (card flies from deck to hand)
t=0.6s  Animation ends → RefreshAllHands() → drawn card NOT in data → NOT shown
t=2.5s  DelayedStateSync fires → ApplyPrivateHand updates data (turnActionRunning=true → no visual)
t=~10s  Animation sequence ends → turnActionRunning = false → no RefreshAllHands()
t=~10s  Card is in data but still NOT visible
t=~??   Next action triggers RefreshAllHands() → card finally appears
```

## Fix

Only **`GameManager.cs`** needs changes. All fixes are in the online-mode-only `PlayTurnResultCoroutine` and `ApplyPrivateHand`.

### Change 1: Add field for pending hand sync (near line ~52)

```csharp
private int[] pendingHandSync = null;
```

### Change 2: Guard `ApplyPrivateHand` during animations (line ~1795)

Prevent `DelayedStateSync` from injecting card data mid-animation. When `turnActionRunning` is true, store the data instead of applying it. After animations complete, discard it (animation code already set correct state).

```csharp
public void ApplyPrivateHand(int[] hand)
{
    if (players == null || playerIdToClientId.Count == 0) return;
    int myId = GetLocalPlayerId(NetworkManager.Singleton.LocalClientId);
    if (myId == -1) return;

    if (turnActionRunning)
    {
        pendingHandSync = hand;
        return;
    }

    players[myId].PlayerHand.Clear();
    foreach (int value in hand)
        players[myId].AddCard(ConvertToCard(value));
    RefreshAllHands();
}
```

### Change 3: CASE 1 SUCCESS — Add transferred cards after animation (line ~2245)

After each transfer animation, add the card to the asker's hand data (matching offline `TransferCardsWithAnimation` line 1170):

```csharp
foreach (int cardValue in data.transferredCards)
{
    Card card = ConvertToCard(cardValue);
    yield return StartCoroutine(
        AnimateCardMove(targetUI.transform, askerUI.transform, card, asker.PlayerID)
    );
    players[asker.PlayerID].AddCard(card);  // ← ADD THIS
}
RefreshAllHands();
```

### Change 4: CASE 1 SUCCESS — Fix book + refill (line ~2285-2365)

**After book animation, also remove refill cards from local hand data** so `RefreshAllHands()` shows empty hand:
```csharp
if (bookLocalId == myLocalId)
{
    List<Card> toRemove = players[bookLocalId].PlayerHand.GetCardsByRank(data.bookRank);
    foreach (Card c in toRemove)
        players[bookLocalId].PlayerHand.RemoveCard(c);

    // Also remove refill cards so they appear only after animation
    if (data.handRefillCards != null && data.handRefillClientId == data.bookPlayerClientId)
    {
        foreach (int refillValue in data.handRefillCards)
        {
            Card refillCard = ConvertToCard(refillValue);
            players[bookLocalId].PlayerHand.RemoveCard(refillCard);
        }
    }
}
```

**In refill animation loop** — add each card AFTER its animation (matching offline `RefillHandIfEmpty` line 971):
```csharp
foreach (int value in data.handRefillCards)
{
    RemoveTopDeckVisual();
    Card refillCard = ConvertToCard(value);
    yield return StartCoroutine(AnimateCardMove(
        deckPosition, refillUI.transform, refillCard, refillPlayerId
    ));
    players[refillPlayerId].AddCard(refillCard);  // ← ADD THIS
}
RefreshAllHands();
```

### Change 5: CASE 3 GO FISH PHASE 2 — Add drawn card after animation (line ~2497)

This is the **primary fix** for the user's reported bug. Add the drawn card to hand data after the animation (matching offline `DrawCardWithAnimation` line 1271):

```csharp
Card drawn = ConvertToCard(data.drawnCardValue);
yield return StartCoroutine(
    AnimateCardMove(deckPosition, askerUI.transform, drawn, asker.PlayerID)
);
players[asker.PlayerID].AddCard(drawn);  // ← ADD THIS
RefreshAllHands();
```

### Change 6: CASE 3 GO FISH PHASE 2 — Fix book + refill (line ~2541-2622)

Same pattern as Change 4: remove refill cards before `RefreshAllHands()`, add them back after each animation.

### Change 7: End of `PlayTurnResultCoroutine` — Clear pending sync (all exit points)

At every `turnActionRunning = false` exit point in `PlayTurnResultCoroutine`, clear the pending sync since the animation code already set the correct state:

```csharp
turnActionRunning = false;
pendingHandSync = null;
```

There are 3 exit points in the coroutine:
1. SUCCESS case → `continueTurn = false` (line ~2406)
2. SUCCESS case → `continueTurn = true` end (line ~2416)
3. GO FISH PHASE 2 end (line ~2652)
