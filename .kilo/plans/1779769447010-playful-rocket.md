# Plan: Book Formation Animation for Online (Play with Friends) Mode

## Problem

In "Play with Friends" (online/multiplayer) mode, when a book (4 cards of same rank) is formed:
1. **Transfer case**: Player has 3 cards of a rank, receives the 4th from opponent → book forms but cards silently disappear. No animation.
2. **Lucky draw case**: Player draws from deck and completes a book → cards silently disappear. No animation.

In offline mode, `HandleBook` coroutine (GameManager.cs:1417) properly animates the 4 cards collecting together using `AnimateCardMove` before removing them from hand.

In online mode, `PlayTurnResultCoroutine` (GameManager.cs:2072) only shows a text toast and waits 2 seconds — no card animation at all. Additionally, `BookCreatedClientRpc` in NetworkGameManager fires separately, causing a **duplicate toast**.

## Root Cause Analysis

### Offline flow (works correctly):
1. `TransferCardsWithAnimation` → `CheckForBook(playerID)` → `HandleBook` coroutine
2. `HandleBook` animates each of the 4 cards via `AnimateCardMove(playerTransform, playerTransform, card, playerID)`
3. Removes cards from hand, updates score, refreshes UI

### Online flow (broken):
1. Server: `CheckForBook` removes cards from `NetworkPlayer.hand` immediately
2. Server: calls `BookCreatedClientRpc` (toast only, no animation)
3. Server: calls `TurnResultClientRpc` with `bookFormed=true`
4. Client: `PlayTurnResultCoroutine` shows a second toast, waits 2 seconds
5. Cards disappear on next `DelayedStateSync` — no visual feedback

### Issues:
- No card animation for book formation (both transfer and draw cases)
- Duplicate toast from `BookCreatedClientRpc` + `PlayTurnResultCoroutine`
- Cards vanish abruptly when `DelayedStateSync` replaces the hand data

### Step 1: Add helper to reconstruct book cards from rank (GameManager.cs)

Add a static helper method that creates 4 Card objects (one per suit) for a given rank. Since a book is always all 4 suits of the same rank, reconstruction from rank alone is always correct and avoids adding new network fields.

```csharp
static List<Card> ReconstructBookCards(int rank)
{
    return new List<Card>
    {
        new Card(rank, CardSuit.Spade),
        new Card(rank, CardSuit.Heart),
        new Card(rank, CardSuit.Diamond),
        new Card(rank, CardSuit.Club)
    };
}
```

Location: Add as a private method in `GameManager` class (around line 2375, before `ConvertToCard`).

### Step 2: Add `AnimateOnlineBook` coroutine (GameManager.cs)

Create a dedicated coroutine for the online book formation animation. This mirrors the animation portion of offline `HandleBook` (lines 1430-1437) but without offline-specific game logic (AI memory, refill hand, deck-empty checks).

```csharp
IEnumerator AnimateOnlineBook(int playerID, int rank)
{
    int uiIndex = GetUIIndex(playerID);
    Transform playerTransform = uiPlayers[uiIndex].transform;

    if (toastUI != null)
    {
        if (players[playerID].IsHuman)
            toastUI.ShowToast("Book forming...");
        else
            toastUI.ShowToast(players[playerID].PlayerName + " book forming...");
    }

    List<Card> bookCards = ReconstructBookCards(rank);
    foreach (Card c in bookCards)
    {
        yield return StartCoroutine(
            AnimateCardMove(playerTransform, playerTransform, c, playerID)
        );
    }
}
```

Key points:
- `AnimateCardMove` (line 1065) instantiates a temporary flying card prefab — it doesn't depend on hand data. Safe to call even after server removed cards.
- `playerTransform → playerTransform` creates the same "collecting" arc animation as offline mode.
- No hand mutation here — that's handled separately.

Location: Add in `GameManager` class, near other coroutines (around line 1331).

### Step 3: Replace book handling in SUCCESS case (GameManager.cs)

In `PlayTurnResultCoroutine`, replace the current book block (lines 2154-2191) with animated version:

**Current code** (lines 2154-2191):
```csharp

{
    int bookLocalId = GetLocalPlayerId(data.bookPlayerClientId);
    Player bookPlayer = players[bookLocalId];
    // ... just sets score, shows toast, waits 2s

```

**New code:**
```csharp
if (data.bookFormed)
{
    int bookLocalId = GetLocalPlayerId(data.bookPlayerClientId);
    yield return StartCoroutine(AnimateOnlineBook(bookLocalId, data.bookRank));

    int myLocalId = GetLocalPlayerId(NetworkManager.Singleton.LocalClientId);
    if (bookLocalId == myLocalId)
    {
        List<Card> toRemove = players[bookLocalId].PlayerHand.GetCardsByRank(data.bookRank);
        foreach (Card c in toRemove)
            players[bookLocalId].PlayerHand.RemoveCard(c);
    }

    players[bookLocalId].SetScore(data.bookPlayerScore);
    uiPlayers[GetUIIndex(bookLocalId)].UpdateScore(data.bookPlayerScore);

    if (toastUI != null)
    {
        if (players[bookLocalId].IsHuman)
            toastUI.ShowToastWithAutoHide("You completed a book!", 3f);
        else
            toastUI.ShowToastWithAutoHide(players[bookLocalId].PlayerName + " completed a book!", 3f);
    }

    RefreshAllHands();
    yield return new WaitForSeconds(2f);
}
```

Key changes:
- Calls `AnimateOnlineBook` before updating state → cards animate visually
- Explicitly removes book cards from local hand (only if this client owns the player) → hand is correct regardless of state sync timing
- `RefreshAllHands()` after removal → UI shows updated hand immediately
- `turnActionRunning` is already `true` at this point, so `DelayedStateSync` won't cause visual conflicts
