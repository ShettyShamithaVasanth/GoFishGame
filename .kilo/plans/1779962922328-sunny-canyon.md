# Fix: NullReferenceException in Online Multiplayer + Game Over + Hand Refill

## Root Cause

The crash occurs in `TurnResultData.NetworkSerialize` (line 66) because **array fields are `null`** when Netcode tries to serialize them. In C# structs, arrays default to `null`. Netcode's `SerializeValue` for arrays does not handle null — it crashes.

### Why arrays are null:

1. **`RequestCardRpc` SUCCESS path** — `FillGameOverData` is called, but it only initializes game-over arrays when the deck is empty. If the deck still has cards, all `gameOver*` arrays stay `null`.

2. **`RequestCardRpc` GO FISH path** — `FillGameOverData` is **never called**. `handRefillCards` is also `null`. All game-over arrays are `null`.

3. **`RequestDrawFromDeckRpc` empty-deck path** — `handRefillCards` is never initialized when `drawnCard == -1`.

## Changes

### 1. `NetworkGameManager.cs` — `TurnResultData` struct (lines 8-73)

Add a static `Create()` factory method that initializes ALL array fields to empty arrays:

```csharp
public static TurnResultData Create()
{
    return new TurnResultData
    {
        transferredCards = new int[0],
        handRefillCards = new int[0],
        gameOverScores = new int[0],
        gameOverPlayerIds = new ulong[0],
        gameOverAvatarIndices = new int[0],
        gameOverIsHuman = new bool[0],
        handRefillClientId = ulong.MaxValue,
        drawnCardValue = -1,
        bookRank = -1,
    };
}
```

### 2. `NetworkGameManager.cs` — `FillGameOverData` method (lines 809-850)

Change the method to **always** initialize arrays. When the deck is not empty, set `isGameOver = false` with empty arrays instead of returning early:

```csharp
void FillGameOverData(ref TurnResultData result)
{
    var players = NetworkPlayerManager.Instance.players;
    result.gameOverScores = new int[players.Count];
    result.gameOverPlayerIds = new ulong[players.Count];
    result.gameOverAvatarIndices = new int[players.Count];
    result.gameOverIsHuman = new bool[players.Count];
    result.gameOverPlayerCount = players.Count;

    for (int i = 0; i < players.Count; i++)
    {
        result.gameOverScores[i] = players[i].score.Value;
        result.gameOverPlayerIds[i] = players[i].OwnerClientId;
        result.gameOverAvatarIndices[i] = players[i].avatarIndex.Value;
        result.gameOverIsHuman[i] = players[i].OwnerClientId == NetworkManager.Singleton.LocalClientId;
    }

    if (NetworkDeckManager.Instance.deck.Count > 0)
    {
        result.isGameOver = false;
        return;
    }

    result.isGameOver = true;
    Debug.Log("[SERVER-GAMEOVER] Game Over Broadcasted");
}
```

### 5. `GameRules.cs` — `GetWinner` method (lines 27-36)

Add null check to handle online mode where `players[]` may have null entries:

```csharp
public static Player GetWinner(Player[] players)
{
    Player winner = null;
    foreach (Player p in players)
    {
        if (p == null) continue;
        if (winner == null || p.Score > winner.Score)
            winner = p;
    }
    return winner;
}
```

### 6. `GameOverUI.cs` — `ShowGameOver` method (lines 17-82)

The existing code already handles null players via `.Where(p => p != null)` (implicit through the activePlayers count in online mode). Verify the `Take(activePlayers)` logic works correctly. The `OrderByDescending` needs a null guard since `players` array may contain nulls:

```csharp
var sortedPlayers = players
    .Where(p => p != null)
    .OrderByDescending(p => p.Score)
    .ThenBy(p => p.LastBookTurn)
    .Take(activePlayers)
    .ToArray();
```

Add `using System.Linq;` if not already present (it is).

### 7. `GameManager.cs` — `TriggerGameOver` method (lines 1561-1627)

Add null check for online mode `players` array when calling `GameRules.GetWinner` and `gameOverUI.ShowGameOver`. The current code may crash if `players[0]` is null in online mode:

```csharp
Player winner = GameRules.GetWinner(players);
if (winner == null) return;
```
