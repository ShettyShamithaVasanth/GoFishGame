# Plan: Online Hand Refill After Book Formation

## Problem
In offline mode, when a player forms a book and their hand becomes empty, `RefillHandIfEmpty` (GameManager.cs:925) draws up to 5 cards from the deck to refill their hand. This feature is **completely missing** in online mode — the `RefillHandIfEmpty` coroutine explicitly bails out with `yield break` when `isOnlineMode` is true (line 941).

## Current Architecture
- **Offline**: `HandleBook` → `RefillHandIfEmpty` → draws `Min(5, deck.CardCount())` cards with animation
- **Online Server**: `CheckForBook(NetworkPlayer)` removes book cards from `NetworkPlayer.hand` but **never refills** an empty hand
- **Online Client**: `PlayTurnResultCoroutine` animates books but has **no refill animation path**

## Changes Required

### 1. Extend `TurnResultData` (NetworkGameManager.cs:8-48)
Add 3 new fields to the network-serializable struct:
```
public bool handRefilled;
public int[] refillCards;
public ulong refillPlayerClientId;
```
Add corresponding `NetworkSerialize` calls for each field.

### 2. Add Server-Side Refill Method (NetworkGameManager.cs)
Add a new private method to `NetworkGameManager`:
```csharp
int[] RefillHandIfEmpty(NetworkPlayer player)
```
- If `player.hand.Count > 0` → return empty array
- Draw `Mathf.Min(5, NetworkDeckManager.Instance.deck.Count)` cards
- Add each to `player.hand`
- Update `deckRemainingCards.Value`
- Return array of drawn card values

### 3. Call Refill After Book Check in `RequestCardRpc` (NetworkGameManager.cs:432-484)
After `CheckForBook(sender)` in the success branch:
```csharp
int bookedRank = CheckForBook(sender);
result.bookFormed = bookedRank != -1;
// ... existing book fields ...

// NEW: Refill if hand empty after book
int[] refillCards = RefillHandIfEmpty(sender);
result.handRefilled = refillCards.Length > 0;
result.refillCards = refillCards;
result.refillPlayerClientId = sender.OwnerClientId;
result.deckRemaining = NetworkDeckManager.Instance.deck.Count;
```

### 4. Call Refill After Book Check in `RequestDrawFromDeckRpc` (NetworkGameManager.cs:491-587)
After `CheckForBook(sender)`:
```csharp
int bookedRank = CheckForBook(sender);
result.bookFormed = bookedRank != -1;
// ... existing book fields ...

// NEW: Refill if hand empty after book
int[] refillCards = RefillHandIfEmpty(sender);
result.handRefilled = refillCards.Length > 0;
result.refillCards = refillCards;
result.refillPlayerClientId = sender.OwnerClientId;
```
Update `result.deckRemaining` after refill to reflect the new deck count.

### 5. Client-Side Refill Animation in `PlayTurnResultCoroutine` (GameManager.cs:2105-2458)
In both the **SUCCESS** case (after book handling, ~line 2248) and the **GO FISH PHASE 2** case (after book handling, ~line 2427), add:

```csharp
// After book animation completes...
if (data.handRefilled)
{
    int refillLocalId = GetLocalPlayerId(data.refillPlayerClientId);
    UIPlayer refillUI = FindUIPlayerByNetworkId(data.refillPlayerClientId);
    
    foreach (int cardValue in data.refillCards)
    {
        RemoveTopDeckVisual();
        Card card = ConvertToCard(cardValue);
        yield return StartCoroutine(
            AnimateCardMove(deckPosition, refillUI.transform, card, refillLocalId)
        );
    }
    
    RefreshAllHands();
    yield return new WaitForSeconds(1f);
}
```

### 6. Update `deckRemaining` After Refill Draw
In both server RPC methods, ensure `result.deckRemaining` and `deckRemainingCards.Value` are set AFTER the refill happens (not before), so clients get the correct deck count.
