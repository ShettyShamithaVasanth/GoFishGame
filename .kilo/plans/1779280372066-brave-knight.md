# Plan: Fix Popup1/Popup2 on Client Side Using FindPlayerByNetworkId

## Problem (from user's screenshot)
When Host asks Client for cards:

**HOST screen** (correct ✅):
- Bottom (Host, profile_anim rotating) = popup1 (ask)
- Top (Client) = popup2 (reply)

**CLIENT screen** (wrong ❌):
- Bottom (Client) = popup1 ← should be popup2
- Top (Host, profile_anim rotating) = popup2 ← should be popup1

## Root Cause
`PlayTurnResultCoroutine` always assigns popups the same way on all clients:
- `askerUI.ShowAskPopup()` → popup1
- `targetUI.ShowReplyPopup()` → popup2

On the CLIENT, the seat mapping puts the local player at bottom (seat 0). When `FindUIPlayerByNetworkId` resolves, the asker UI maps to the top player and target UI maps to the bottom player. But the **profile_anim rotation** follows the `HandleTurnChanged` event which fires based on `ApplyNetworkTurn` — and on the client, the host's UIPlayer gets `StartTurnAnimation()` (profile_anim rotating at top).

So on CLIENT screen:
- Top (Host) has profile_anim rotating ← this player should show popup1 (they're asking)
- Bottom (Client) is being asked ← this player should show popup2 (replying)

But currently it shows reversed. The fix: detect which client this is, and if this client is the **target**, swap popup assignments.

## Fix: 1 File — `GameManager.cs`

### Add role detection after `askerUI`/`targetUI` are found (after line 2103):

```csharp
ulong myClientId = NetworkManager.Singleton.LocalClientId;
bool iAmTarget = (data.targetClientId == myClientId);

UIPlayer localAskUI = iAmTarget ? targetUI : askerUI;
UIPlayer localReplyUI = iAmTarget ? askerUI : targetUI;
```

This means:
- **If I am the target** (being asked): I see popup1 (the question), the asker sees popup2 (their reply)
- **If I am the asker** (asking): I see popup1 (my ask), the target sees popup2 (their reply) — same as current behavior
