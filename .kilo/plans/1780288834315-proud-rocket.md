# Fix: Online Gameplay Animation Sequence — Complete Root Cause

## Problem

In **Play with Friends (online)** mode, when a player completes a book and hand refills from deck:

**Current broken sequence:**
1. Deck disappears
2. Book forms
3. Hand cards appear (refill cards show in hand)
4. Card animation from deck plays (too late — cards already visible)

**Desired sequence (matching offline):**
1. Book formation animation
2. Deck becomes empty (card-by-card)
3. Cards animate from deck to player hand
4. Hand shows new cards (only AFTER animation)

## Root Cause — 3 Interrelated Issues

### Issue 1: `ApplyPrivateHand` updates hand DATA during animation (NOT just visual)

`GameManager.cs` line 1792 — `ApplyPrivateHand`:
```csharp
public void ApplyPrivateHand(int[] hand)
{
    // ... null checks (NO turnActionRunning guard on data!) ...
    players[myId].PlayerHand.Clear();          // ← DATA updated during animation
    foreach (int value in hand)
        players[myId].AddCard(ConvertToCard(value)); // ← refill cards added to data
    if (!turnActionRunning)                     // ← only VISUAL refresh guarded
        RefreshAllHands();
}
```

`DelayedStateSync(5f)` fires at server T=5s. The ~10s animation is still running. This method:
- **Clears** the local player's hand data and **rebuilds** it with the final state (including refill cards)
- Only blocks `RefreshAllHands()` visual refresh
- But the coroutine later calls `RefreshAllHands()` (line 2322), which renders the already-updated data showing refill cards **before** the refill animation plays

### Issue 2: `ApplyPublicState` updates scores/card counts during animation

`GameManager.cs` line 1758 — `ApplyPublicState`:
```csharp
public void ApplyPublicState(ulong[] ids, int[] scores, int[] cardCounts)
{
    // ... null checks (NO turnActionRunning guard on data!) ...
    players[localId].SetScore(scores[i]);  // ← score updated during animation
    // ... card count updates for non-local players ...
    if (!turnActionRunning)
        RefreshAllHands();  // ← only visual guarded
}
```

Same pattern: data updated during animation, visual refresh guarded.

### Issue 3: `UpdateDeckVisualCount` calls in coroutine are blocked by own guard

`GameManager.cs` line 395 — the `turnActionRunning` guard:
```csharp
public void UpdateDeckVisualCount(int remainingCards)
{
    if (turnActionRunning) return;  // ← blocks ALL calls during animation
    ...
}
```

The coroutine calls `UpdateDeckVisualCount(data.deckRemaining)` at line 2368 (SUCCESS) and 2621 (GO FISH Phase 2), but at those points `turnActionRunning` is still `true`. So the calls are **self-blocked**. The deck visual only gets updated by `RemoveTopDeckVisual()` calls in refill loops (which is correct for incremental updates), but the final safety sync never runs.

### Issue 4: Refill animation doesn't add cards to local hand data

In the refill loops (lines 2335-2351, 2591-2607), cards are animated but never added to the player's hand:
```csharp
foreach (int value in data.handRefillCards)
{
    RemoveTopDeckVisual();     // ✓ removes deck visual
    Card refillCard = ConvertToCard(value);
    yield return StartCoroutine(AnimateCardMove(...));  // ✓ animates
    // ❌ missing: players[refillPlayerId].AddCard(refillCard);
}
RefreshAllHands();  // shows stale hand data
```

In offline mode's `RefillHandIfEmpty()` (line 968), `player.AddCard(drawn)` is called after each animation. Online mode is missing this.

## Changes — `Assets/Scripts/GameManager.cs` Only

### Change 1: Guard `ApplyPrivateHand` completely (line ~1792)

Block ALL updates (data + visual) during animation:

```csharp
public void ApplyPrivateHand(int[] hand)
{
    if (players == null || playerIdToClientId.Count == 0)
        return;
    if (turnActionRunning) return;  // ← NEW: block data update too
    // ... rest unchanged
}
```

public void ApplyPublicState(ulong[] ids, int[] scores, int[] cardCounts)

## What Does NOT Change

- **Offline gameplay** — No changes. Offline doesn't use `ApplyPrivateHand`, `ApplyPublicState`, or `DelayedStateSync`.
- **Lobby/room system** — No lobby, room, or matchmaking code touched.
- **NetworkGameManager server logic** — No server-side RPCs or book/deck logic changed.
- **MVC structure** — Same architecture. Changes are in the Controller layer (animation state management).
- **Turn flow logic** — Game state, turn management, winner determination all identical.

## Result — Corrected Online Animation Sequence

After all fixes:
1. Transfer animation (or draw animation) plays
2. **Book formation animation** plays
3. Book cards removed from hand, score updated
4. `RefreshAllHands()` shows hand without book cards (correct — no premature refill cards)
5. **Deck visual decreases** one-by-one via `RemoveTopDeckVisual()`
6. **Refill cards animate** from deck position to player
7. Cards added to hand data (matching offline `player.AddCard(drawn)`)
8. `RefreshAllHands()` shows new cards (only after animation)
9. `turnActionRunning = false` → `UpdateDeckVisualCount` confirms deck state
10. Subsequent state syncs pass through normally

This matches the offline mode behavior exactly and provides a professional Go Fish multiplayer experience.
