## Fix Strategy

### Fix #1 & #2: Use `pollInterval` and `pollTimer` in `Update()`

Add the polling logic that was intended for these fields. The `Update()` method currently only handles timeout — it should also poll the lobby periodically.

```csharp
private void Update()
{
    if (!isSearching) return;

    searchTimer += Time.deltaTime;
    pollTimer    += Time.deltaTime;

    // Poll lobby for player changes every pollInterval seconds
    if (pollTimer >= pollInterval)
    {
        pollTimer = 0f;
        _ = PollLobby();   // fire-and-forget async poll
    }

    if (searchTimer >= searchTimeout)
    {
        HandleTimeout();
    }
}
```

This uses BOTH `pollTimer` and `pollInterval` → eliminates CS0414 for both fields.

`PollLobby()` will be an `async void` method that:
1. Calls `LobbyService.Instance.GetLobbyAsync(currentLobby.Id)`
2. Compares player list → fires `OnPlayerJoined` / `OnPlayerLeft`
3. Checks if 4 players reached → calls `CheckMatchReady()`

Since the method body has only placeholder comments (Relay/StartHost logic not yet implemented), add a single `await` to silence CS1998 while keeping the signature `async Task` so future implementation is seamless:

## Phase 1: Create `QuickMatchService.cs` (NEW FILE)

**Path**: `Assets/Scripts/QuickMatchService.cs`

A MonoBehaviour that handles quick match lobby logic using Unity Lobby Service.

### Class Structure
```csharp
public class QuickMatchService : MonoBehaviour
{
    public static QuickMatchService Instance;

    [Header("Config")]
    public int requiredPlayers = 4;      // must find 4 to start online
    public float searchTimeout = 20f;    // 20 second search window
    public float pollInterval = 2.5f;    // poll lobby every 2.5s
    public AvatarDatabase avatarDatabase;

    // Events for UI
    public event System.Action<string, int, int> OnPlayerJoined;   // (name, avatarIdx, slotIdx)
    public event System.Action<int> OnPlayerLeft;                   // (slotIdx)
    public event System.Action OnMatchFound;                        // 4 players found!
    public event System.Action OnTimeout;                           // 20s expired
    public event System.Action<string> OnError;                     // error message

    Lobby currentLobby;
    bool isSearching;
    float searchTimer;
    float pollTimer;
    bool isHost;
    string relayCode;
}
```

### Key Methods

**`async void FindMatch()`**
1. Set `isSearching = true`
2. Try `Lobbies.Instance.QuickJoinLobbyAsync()` with a lobby query filter for `lobbyType = "QuickMatch"`
3. If QuickJoin fails (no lobbies available) → call `CreateQuickMatchLobby()`
4. If QuickJoin succeeds → call `OnJoinedLobby()`
5. Start polling in `Update()`

**`async Task CreateQuickMatchLobby()`**
1. `Lobbies.Instance.CreateLobbyAsync("QuickMatch", requiredPlayers)`
2. Add lobby data: `{ "lobbyType": "QuickMatch" }` so others can find it
3. Set player data: `{ "name": ProfileData.PlayerName, "avatar": ProfileData.PlayerAvatarIndex }`
4. `isHost = true`
5. Fire events for Player 0

**`async Task OnJoinedLobby()`**
1. Set player data: `{ "name": ProfileData.PlayerName, "avatar": ProfileData.PlayerAvatarIndex }`
2. `isHost = false`
3. Read current lobby players → fire `OnPlayerJoined` for each existing player
4. Read `relayCode` from lobby data if host already created it

**`Update()` polling** (only while `isSearching`)
1. Increment `searchTimer`
2. Poll lobby every `pollInterval` seconds
3. On each poll, compare player list → fire `OnPlayerJoined` for new players
4. If `currentLobby.Players.Count >= requiredPlayers`:
   - Fire `OnMatchFound`
   - Call `StartOnlineGame()`
5. If `searchTimer >= searchTimeout`:
   - Fire `OnTimeout`
   - Call `CleanupAndFallback()`

**`async void StartOnlineGame()`**
- If `isHost`:
  1. Create Relay allocation (`RelayService.Instance.CreateAllocationAsync(4)`)
  2. Get join code → store in lobby data as `relayCode`
  3. Configure `UnityTransport` with relay server data
  4. `NetworkManager.Singleton.StartHost()`
  5. Wait for `NetworkGameManager.Instance` to exist
  6. Call `NetworkGameManager.Instance.InitializeAndDeal()`
- If `!isHost`:
  1. Read `relayCode` from lobby data (poll until available)
  2. Join Relay allocation (`RelayService.Instance.JoinAllocationAsync(relayCode)`)
  3. Configure `UnityTransport` with relay server data
  4. `NetworkManager.Singleton.StartClient()`

**`async void CancelMatchmaking()`**
1. Leave lobby if in one
2. Reset state
3. `isSearching = false`

**`async void CleanupAndFallback()`**
1. Leave lobby
2. Stop network if started
3. `isSearching = false`

   - Card dealing
   - Turn management

## Key Design Decisions

1. **All 4 players required for online**: The game starts online ONLY when all 4 slots are filled within 20s. Otherwise falls back to offline with AI. This keeps the online experience consistent (always 4 players).

2. **Separate QuickMatchService from LobbyManager**: `LobbyManager` handles "Play with Friends" (room codes, manual start). `QuickMatchService` handles "Play Online" (auto-match, auto-start). No cross-contamination.

3. **Reuse existing network infrastructure**: `NetworkPlayer`, `NetworkGameManager`, `NetworkDeckManager`, `PlayerSeatMapper` all already work correctly for multiplayer. QuickMatchService only handles the lobby/relay/connection phase.

4. **Player data format**: Same `{ "name": "...", "avatar": "0" }` format as LobbyManager for consistency.

5. **Configurable fields**: `requiredPlayers`, `searchTimeout`, `pollInterval` are all `[SerializeField]` fields on QuickMatchService — no hardcoding.

6. **Clean MVC separation**:
   - **Model**: `QuickMatchService` (lobby state, player data, network connection)
   - **View**: `MatchmakingUIController` (UI updates, player slots, timer display)
   - **Controller**: `MatchMakingStarter` (orchestrates the flow entry point)
