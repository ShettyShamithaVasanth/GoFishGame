# Plan: Fix Book Formation → Refill Animation Timing

## Problem
When a book forms and the player's hand becomes empty, the refill card should:
1. Show empty hand first
2. Then animate card from deck to hand
3. Then show the card in hand

Currently, the card appears in hand before/during the animation in some cases, particularly in online mode.

## Root Causes Identified

### 1. Offline: `HandleBook` runs as fire-and-forget coroutine
`CheckForBook()` (line 1426) starts `HandleBook` via `StartCoroutine` but does NOT yield. The caller (`DrawCardWithAnimation` or `TransferCardsWithAnimation`) continues immediately:
- `DrawCardWithAnimation` sets `turnActionRunning = false` (line 1356) while `HandleBook` is still animating
- `DrawCardWithAnimation` may call `EndTurn()` while book animation plays
- Multiple `EndGameAfterDelay` coroutines can start simultaneously

### 2. Online: Refill cards NOT added to player model after animation
In `PlayTurnResultCoroutine` (lines 2327-2365), the refill cards are only animated visually. The player model is updated by `DelayedStateSync` at unpredictable times. When state sync arrives during animation and updates the model, the next `RefreshAllHands()` shows cards that shouldn't be visible yet.

### 3. Online: Transferred cards NOT added to player model after animation
In `PlayTurnResultCoroutine` SUCCESS case (lines 2245-2257), transferred cards are animated but not added to the local player model. Book card removal at line 2287 uses `GetCardsByRank` on a model that may not have the cards yet (depends on state sync timing).

### 4. `turnActionRunning` flag mismanagement
`DrawCardWithAnimation` sets `turnActionRunning = false` (line 1356) right after `CheckForBook()`, which runs immediately since `HandleBook` is fire-and-forget. This means `turnActionRunning` is `false` during book animation, allowing state sync to refresh the UI.

## Changes

### File: `Assets/Scripts/GameManager.cs`

#### Change 1: Convert `CheckForBook` to a yieldable coroutine

**Current** (void method, fire-and-forget):
```csharp
void CheckForBook(int playerID)
{
    // ...
    StartCoroutine(HandleBook(playerID, rank, cards));
    // caller continues immediately
}
```

**New**: Create `CheckForBookCoroutine` as IEnumerator. Keep old `CheckForBook` as a thin wrapper for any remaining non-coroutine callers.

```csharp
IEnumerator CheckForBookCoroutine(int playerID)
{
    var result = GameRules.CheckForBook(players[playerID]);
    if (result == null) yield break;

    int rank = result.Value.rank;
    List<Card> cards = result.Value.cards;

    // ... toast, completedRanks, aiMemory, bookJustFormed ...

    yield return StartCoroutine(HandleBook(playerID, rank, cards));

    // Deck empty check AFTER book fully completes
    if (!GameModeManager.isOnlineMode && deck != null && deck.CardCount() == 0)
    {
        StartCoroutine(EndGameAfterDelay());
        yield break; // game ending, no further turn logic
    }
}
```

#### Change 2: Fix `DrawCardWithAnimation` — yield for book check

**Current** (line 1280):
```csharp
CheckForBook(currentPlayer);
```

**New**:
```csharp
yield return StartCoroutine(CheckForBookCoroutine(currentPlayer));
```

Remove the redundant `EndGameAfterDelay` check at lines 1359-1366 since `CheckForBookCoroutine` now handles it after the book completes.

Remove `turnActionRunning = false` at line 1356 — move it to AFTER the book check completes. The new flow:

```
1. Animate draw
2. Add card to model
3. RefreshAllHands() — shows drawn card
4. Wait 1.5s
5. Yield for CheckForBookCoroutine (blocks until book animation + refill complete)
6. THEN decide turn (continue/end)
7. THEN set turnActionRunning = false
8. THEN check deck empty for game end
```

#### Change 4: Simplify `HandleBook` — remove redundant end-game checks

Since `CheckForBookCoroutine` now handles the deck-empty → game-end check AFTER `HandleBook` completes, remove the duplicate checks from `HandleBook` (lines 1517-1523).

Keep `bookJustFormed` flag only for `EndTurn` delay logic (already handled correctly with 5s delay).

#### Change 5: Fix online `PlayTurnResultCoroutine` — SUCCESS case with book

**Location**: Lines 2520-2623

Same fixes as Change 5: add drawn card and refill cards to model after animations, add pause before refill.

#### Change 7: Fix `EndTurn` deck-empty check

**Current** (line 486):
```csharp

{

```

This check is fine but could fire while `HandleBook` is still running (if reached via the old fire-and-forget flow). With the new awaited `CheckForBookCoroutine`, this is no longer a concern, but keep it as a safety net.
