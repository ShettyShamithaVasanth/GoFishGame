# Fix: Online Gameplay Animation Order (Book → Deck Empty → Refill)

## Problem

In **Play with Friends (online)** mode, when a player completes a book and their hand becomes empty, the animation sequence is visually incorrect:

**Current (broken) online behavior:**
1. Deck disappears too early (state sync fires at unpredictable time)
2. Book forms
3. Hand cards fill from deck (no animation, just appear)
4. Animation of cards from deck plays (late, after cards already shown)

**Desired (correct) behavior:**
1. Book forms (animation)
2. Deck becomes empty (visual update)
3. Cards animate from deck position to player hand

**Root cause:** In `GameManager.PlayTurnResultCoroutine()` (lines 2176–2651), `UpdateDeckVisualCount(data.deckRemaining)` is called AFTER all book handling and refill animations finish. The deck visual should be updated BEFORE the refill animation, so the deck shows the correct (possibly empty) state, then cards fly from that position.

**Offline mode is unaffected** — it already works correctly because `RefillHandIfEmpty()` calls `RemoveTopDeckVisual()` one card at a time during each draw animation.

## Changes

### File: `Assets/Scripts/GameManager.cs`

#### Change 1: SUCCESS case with book (lines ~2317–2360)

Move `UpdateDeckVisualCount(data.deckRemaining)` from after the entire book block (line 2360) to inside the book block, right AFTER `RefreshAllHands()` (line 2317) and BEFORE the refill animation starts (line 2319).

**Before:**
```csharp
// Inside if (data.bookFormed) block:
RefreshAllHands();                    // Line 2317

if (data.handRefillCards != null...)  // Line 2319 - refill starts
{
    // ... refill animation
}

yield return new WaitForSeconds(2f);

// Outside if (data.bookFormed) block:
UpdateDeckVisualCount(data.deckRemaining);  // Line 2360 - TOO LATE
```

**After:**
```csharp
// Inside if (data.bookFormed) block:
RefreshAllHands();                           // Line 2317

UpdateDeckVisualCount(data.deckRemaining);   // NEW: deck shows final count BEFORE refill

if (data.handRefillCards != null...)         // Line 2319 - refill starts
{
    // ... refill animation
}

yield return new WaitForSeconds(2f);

// Keep original UpdateDeckVisualCount at line 2360 (harmless no-op for book cases)
```

## What Does NOT Change

- **Offline gameplay** — `RefillHandIfEmpty()` in offline mode works correctly with one-at-a-time deck draws. No changes.
- **Lobby system** — No lobby or room code is touched.
- **NetworkGameManager server logic** — No server-side RPC or book-checking logic changes.
- **MVC structure** — No architectural changes.
- **Turn flow logic** — Only the visual animation order changes; game state and turn management remain identical.

## Result

After fix, online animation sequence:
1. Cards transfer (or draw card animation) completes
2. Book formation animation plays
3. Book cards removed, score updated, hand refreshed (shows empty)
4. **Deck visual updates to final count** (deck becomes empty/smaller)
5. Refill cards animate from deck position to player
6. Hand refreshed (shows new cards)

This matches the desired professional Go Fish flow for both offline and online modes.
