# Fix: Online Go Fish — Card Showing Twice + Multiple Sync & Data Issues

## Problem Description

In **online "Play with Friends" mode**, when a card is drawn from the deck (Go Fish):
1. The card appears in the hand → then all cards briefly disappear → then reappear ("showing twice")
2. Console shows hand count = N+1, then after a few seconds corrects to N (or stays N+1)
3. The visual flicker makes it look like the same card is duplicated

## Root Cause Analysis

### Primary Cause: Visual Flicker from Multiple `RefreshAllHands()` Calls

`RefreshAllHands()` **destroys ALL card GameObjects and creates new ones** every time it's called. When multiple calls happen in quick succession, cards flicker (disappear for 1 frame → reappear).

**The flicker chain:**
1. **Phase 2 coroutine** adds drawn card locally → calls `RefreshAllHands()` → cards show correctly
2. **2.5s later**, `DelayedStateSync` fires → `BroadcastStateToAll()` sends 2 RPCs:
   - `SyncPublicStateClientRpc` → `ApplyPublicState()` → `RefreshAllHands()` → **FLICKER #1**
   - `SyncPrivateHandClientRpc` → `ApplyPrivateHand()` → `RefreshAllHands()` → **FLICKER #2**
3. Both calls destroy and recreate all card visuals even though the data hasn't changed

**Additionally**: Multiple `DelayedStateSync` coroutines pile up from previous turns (Phase 1: 5s delay, Phase 2: 2.5s delay). Each fires independently, causing even more flicker.

### Secondary Cause: CASE 1 (Success) Data Bugs

In `PlayTurnResultCoroutine()` CASE 1 (transfer success):

**Bug A** — Transferred cards NOT added to local hand in the main flow:
```
Lines 2244-2260: Cards are animated but never added to local Player object
→ RefreshAllHands() reads from Player.Hand → transferred cards don't appear
→ They only appear when DelayedStateSync fires later
```

**Bug B** — Transferred cards RE-ANIMATED inside book+refill block:
```
Lines 2356-2371: Inside the book+refill block, transferred cards are animated AGAIN
→ The same cards fly from target to asker TWICE (visual duplicate animation)
```

**Bug C** — Refill cards NOT added to local hand in both CASE 1 and CASE 3:
```
Lines 2338-2354 (CASE 1) and 2625-2641 (CASE 3):
Refill cards are animated but never added to Player.Hand
→ RefreshAllHands() doesn't show them until sync fires
```

### Change 4: `GameManager.cs` — Make `ApplyPrivateHand` skip unchanged refreshes

**Location**: `ApplyPrivateHand()` method (~line 1795)

**What**: Compare incoming hand data with current local hand. Skip the clear+rebuild+refresh if data is identical.

```csharp
public void ApplyPrivateHand(int[] hand)
{
    if (players == null || playerIdToClientId.Count == 0)
        return;

    int myId = GetLocalPlayerId(NetworkManager.Singleton.LocalClientId);
    if (myId == -1) return;

    var currentCards = players[myId].PlayerHand.Cards;

    if (currentCards.Count == hand.Length && hand.Length > 0)
    {
        bool changed = false;
        for (int i = 0; i < hand.Length; i++)
        {
            int localValue = currentCards[i].Rank * 10 + (int)currentCards[i].Suit;
            if (localValue != hand[i])
            {
                changed = true;
                break;
            }
        }
        if (!changed) return;
    }

    players[myId].PlayerHand.Clear();
    foreach (int value in hand)
    {
        players[myId].AddCard(ConvertToCard(value));
    }
    if (!turnActionRunning)
        RefreshAllHands();
}
```

### Change 5: `GameManager.cs` — Make `ApplyPublicState` skip unchanged refreshes

**Location**: `ApplyPublicState()` method (~line 1756)

**What**: Track previous public state and skip refresh if nothing changed. Add a simple count-based check to avoid unnecessary `RefreshAllHands()` calls.

```csharp
public void ApplyPublicState(ulong[] ids, int[] scores, int[] cardCounts)
{
    if (players == null || activePlayers == null)
        return;

    int myId = GetLocalPlayerId(NetworkManager.Singleton.LocalClientId);
    bool changed = false;

    for (int i = 0; i < ids.Length; i++)
    {
        int localId = GetLocalPlayerId(ids[i]);
        if (localId == -1) continue;

        if (players[localId].Score != scores[i])
        {
            players[localId].SetScore(scores[i]);
            changed = true;
        }

        if (localId != myId)
        {
            int currentCount = players[localId].PlayerHand.Cards.Count;
            int targetCount = cardCounts[i];
            if (currentCount != targetCount)
            {
                players[localId].PlayerHand.Clear();
                for (int j = 0; j < targetCount; j++)
                {
                    players[localId].AddCard(new Card(0, CardSuit.Spade));
                }
                changed = true;
            }
        }
    }

    if (changed && !turnActionRunning)
        RefreshAllHands();
}
```

### Change 6: `NetworkGameManager.cs` — Cancel previous `DelayedStateSync` when starting new one

Create a helper method:

```csharp
void StartStateSync(float delay)
{
    if (activeStateSync != null)
    {
        StopCoroutine(activeStateSync);
    }
    activeStateSync = StartCoroutine(DelayedStateSync(delay));
}
```

Replace all `StartCoroutine(DelayedStateSync(...))` calls with `StartStateSync(...)`:

## Why These Changes Are Safe

1. **No offline impact**: All changes are in online-only code paths (`PlayTurnResultCoroutine` is gated by `if (!GameModeManager.isOnlineMode) return;`)

2. **No data corruption**: `ApplyPrivateHand` always clears and rebuilds from server data. The "skip if unchanged" check just prevents unnecessary UI refreshes.

3. **No lobby/gameplay side effects**: Only local Player data model and sync timing are affected. Network RPC flow is unchanged.

4. **Cancel stale syncs is safe**: The latest sync always contains the most current server state. Cancelling a previous stale sync prevents it from overwriting with outdated data.
