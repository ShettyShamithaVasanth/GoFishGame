# Fix Plan — QuickMatchService Compilation Error + Flow Verification

## Root Cause

**`QuickMatchService.cs` lines 456 and 468 fail to compile.**

The project has two `Player` classes:
1. `Assets/Scripts/core/Player.cs:4` — `public class Player` (global namespace — the game model)
2. `Unity.Services.Lobbies.Models.Player` — the Lobby SDK player type

Both are in scope via `using Unity.Services.Lobbies.Models;` (line 3). When the compiler sees `Player p` in the method signatures, it can't resolve which one. **This is the build-breaking error.**

---

## Fix (1 file, 2 lines)

### `Assets/Scripts/QuickMatchService.cs` — Change lines 456 and 468

**Line 456** — change:
```csharp
// BEFORE (ambiguous):
private string ResolvePlayerName(Player p)

// AFTER (fully qualified):
private string ResolvePlayerName(Unity.Services.Lobbies.Models.Player p)
```

**Line 468** — change:
```csharp
// BEFORE (ambiguous):
private int ResolvePlayerAvatar(Player p)

// AFTER (fully qualified):
private int ResolvePlayerAvatar(Unity.Services.Lobbies.Models.Player p)
```

That's it. No other compilation errors exist — all other types (`Lobby`, `DataObject`, `Allocation`, `JoinAllocation`, etc.) have no conflicts.

## Implementation

Change exactly 2 lines in `Assets/Scripts/QuickMatchService.cs`:

1. Line 456: `private string ResolvePlayerName(Player p)` → `private string ResolvePlayerName(Unity.Services.Lobbies.Models.Player p)`
2. Line 468: `private int ResolvePlayerAvatar(Player p)` → `private int ResolvePlayerAvatar(Unity.Services.Lobbies.Models.Player p)`

Then build. The matchmaking flow should work:
- Host: creates lobby + relay → shows own slot → polls → other players appear → 4 players → auto-start
- Client: queries lobbies → joins → sees all players → waits for host to start
- Timeout: 20s → cleanup → offline fallback (same as before)
