# Fix: Online Go Fish Drawn Card Appears Doubled

## Issue

In **online "Play with Friends" mode**, when Player A asks Player B for a rank, B doesn't have it (Go Fish), and Player A draws from the deck — the drawn card briefly appears **twice (doubled)** in Player A's hand for ~1 second, then self-corrects.

Offline mode works correctly. Only online mode is affected.

## Root Cause

**`ApplyPrivateHand` modifies hand data during animation, causing double-add.**

The flow is:

1. Server processes draw → adds card to `NetworkPlayer.hand` → sends `TurnResultClientRpc` (Phase 2) → starts `DelayedStateSync(2.5f)`
2. Client receives Phase 2 result → sets `turnActionRunning = true` → starts card animation → **yields**
3. **During the yield** (animation running), a server state sync arrives → `SyncPrivateHandClientRpc` → `ApplyPrivateHand` runs:
   - Clears local `Player.hand`
   - Re-adds all cards from server (including the drawn card)
   - Skips UI refresh because `turnActionRunning == true`
4. Animation completes → `players[asker.PlayerID].AddCard(drawn)` adds drawn card **AGAIN** → **doubled in data**
5. `RefreshAllHands()` → shows doubled card visually
6. Later state sync → `ApplyPrivateHand` clears + re-adds correctly → visual corrects

**The same bug can also affect the SUCCESS case** (card transfer animation) with the same pattern.

## Fix (Single File: `Assets/Scripts/GameManager.cs`)

### Change 1: Guard `ApplyPrivateHand` during animation

**Method**: `ApplyPrivateHand` (line ~1795)

**Current behavior**: Modifies hand data during animation but skips UI refresh.
**New behavior**: Skip the ENTIRE method during animation — don't touch hand data at all.

```csharp
// BEFORE:
public void ApplyPrivateHand(int[] hand)
{
    if (players == null || playerIdToClientId.Count == 0)
        return;
    int myId = GetLocalPlayerId(NetworkManager.Singleton.LocalClientId);
    if (myId == -1) return;

    players[myId].PlayerHand.Clear();
    foreach (int value in hand)
    {
        players[myId].AddCard(ConvertToCard(value));
    }
    if (!turnActionRunning)
        RefreshAllHands();
}

// AFTER:
public void ApplyPrivateHand(int[] hand)
{
    if (players == null || playerIdToClientId.Count == 0)
        return;
    int myId = GetLocalPlayerId(NetworkManager.Singleton.LocalClientId);
    if (myId == -1) return;

    if (turnActionRunning)
        return;

    players[myId].PlayerHand.Clear();
    foreach (int value in hand)
    {
        players[myId].AddCard(ConvertToCard(value));
    }
    RefreshAllHands();
}
```

**Why this is safe**: The local `PlayTurnResultCoroutine` code correctly adds cards locally after animations. After `turnActionRunning` becomes false, the next state sync (which fires periodically via `DelayedStateSync`) will ensure final consistency.

### Change 2: Add refill cards locally in online Phase 2 (CASE 3)

**Method**: `PlayTurnResultCoroutine`, inside CASE 3 book refill block (~line 2595)

The online refill animation code animates cards but never adds them to the local player's hand data. It was relying on `ApplyPrivateHand` from state sync to add them. With Change 1 skipping syncs during animation, we need to add refill cards locally.

```csharp
// BEFORE (inside handRefillCards loop):
foreach (int value in data.handRefillCards)
{
    RemoveTopDeckVisual();
    Card refillCard = ConvertToCard(value);
    yield return StartCoroutine(
        AnimateCardMove(deckPosition, refillUI.transform, refillCard, refillPlayerId)
    );
}

// AFTER:
foreach (int value in data.handRefillCards)
{
    RemoveTopDeckVisual();
    Card refillCard = ConvertToCard(value);
    yield return StartCoroutine(
        AnimateCardMove(deckPosition, refillUI.transform, refillCard, refillPlayerId)
    );
    players[refillPlayerId].AddCard(refillCard);
}
```
